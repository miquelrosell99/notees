- **fix(ci): the release guard fetches the tag's parent — the first monorepo tag (`word-v0.1.0`, guard-only failure, nothing published) is superseded by word-v0.1.1.** Same story as the GTK entry: the scope check diffs the tagged commit with `git show --name-only`; the checkout v7 partial clone left no parent and the check misfired. `fetch-depth: 2` on the guard's checkout fixes it.   - Files: root `.github/workflows/release-word.yml` (+ the same guard fix across the sibling release workflows), `CHANGELOG.md`.

- **chore(word): joined the Notees monorepo as `clients/word` — CI moved to the repo root behind a path filter, and a `word-v*` tag pipeline now publishes the built dist as a release zip.** The add-in's history merged into the unified `notees` repo; the standalone repo's CI workflow moved to `.github/workflows/ci-word.yml` at the monorepo root — same gate (`pnpm build`, `pnpm typecheck`, `pnpm test`), now scoped with a `clients/word/**` pull_request path filter so work elsewhere in the monorepo does not spend this gate's runner. Releases: pushing a `word-v*` tag runs `.github/workflows/release-word.yml` — a guard job fails the run unless the tagged commit touches `clients/word/`, then install + build + test, `zip -r notees-word-<tag>.zip dist/` (run from `clients/word/` so the paths inside the zip are `dist/...`), and the zip attaches to the tag's GitHub Release. One scaffolding addition rides along: `pnpm-workspace.yaml` (`packages: []`) fences the client off from the monorepo root workspace — without it pnpm ascends to the root `pnpm-workspace.yaml` and silently installs the core workspace instead of this client's own lockfile. Paths below are from the monorepo root. Verification: `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm typecheck` clean; `pnpm test` 152/152 (16 files).
  - Files: `.github/workflows/ci-word.yml`, `.github/workflows/release-word.yml`, `clients/word/.github/workflows/ci.yml` (deleted), `clients/word/pnpm-workspace.yaml`.

## 2026-11-16
- **ci(word): the gate runs on PRs + a 03:23 UTC nightly cron over main's head — the `push: [main]` trigger retires per the fleet trigger matrix (owner directive 2026-11-16).** The nightly cron covers main's head — per-push CI on main was a recurring failure source, so it is gone, not replaced. `workflow_dispatch` re-runs the gate on demand, and a concurrency block cancels superseded runs. The runner pins `ubuntu-22.04` (never `ubuntu-latest`) and every action is SHA-pinned with a version comment (checkout v7.0.0, setup-node v7.1.0 — the fleet-verified pins). The gate itself is unchanged: `pnpm build`, `pnpm typecheck`, `pnpm test`.
  - Files: `.github/workflows/ci.yml`.

- **feat(word): the pane is backend-agnostic — same-origin `/api/*` against the `notees word serve` gateway, no server URL or API key anywhere in the pane.** The gateway (Notees CLI) now proxies the pane's `/api/*` calls to the configured sync server with the credential injected server-side, so the pane only ever talks to its own origin. New `src/api/client.ts` is the seam: root-relative `/api/` paths only — an absolute URL is a programmer error thrown before fetch, so pane code can never escape the gateway or leak a credential. The settings store migrates pre-gateway records: a stored `notees.addin.settings.v1` that carried its own `serverUrl`/`apiKey` (or any stray fields) loads without breaking and is rewritten to the canonical `{port, token, styleId}` shape on first load; canonical records are not rewritten. The README states the two-local-backends model (gateway + citation bridge), documents the self-migration, and the smoke checklist gains a gateway-only network-trace item. Verification: `pnpm typecheck` clean; `pnpm test` 152/152 (16 files — 8 new specs: 5 api-client + 3 settings-migration); `pnpm build:localhost` clean.
- **feat(word): localhost build flavor — the add-in statics are built for local serving by `notees word serve`, replacing the retired `/word/` prod hosting.** The sync server no longer serves the add-in; the Notees CLI now serves the statics on the machine running Word (`notees word serve`, which serves the vendored build at `http://localhost:8471` and renders the sideload manifest per port into its per-user cache dir). The manifest template gains a second placeholder, `${BASE_PATH}` (default `/word`, overridable via `NOTEES_WORD_BASE_PATH`), so the default build keeps the exact `/word/` URLs it always rendered; `pnpm build:localhost` renders the root-served layout — `${HOST}` defaults to `http://localhost:8471`, `${BASE_PATH}` to "". `scripts/copy-manifest.mjs` takes the flavor as an argv word, keeps the env overrides, exports the render functions for the test suite (with a small `.d.mts` for tsc), and fails the build on any unresolved placeholder. The README and the smoke checklist document the `notees word serve` serving contract; sideloading points at the CLI's cache-dir manifest, and pairing documents the `--origin http://localhost:8471` the bridge now needs. Verification: `pnpm typecheck` clean; `pnpm test` 144/144 (15 files — four new manifest-render specs on top of the unchanged scaffold pin, which still pins the default-flavor `/word/` dist); both flavors build clean (`pnpm build`, `pnpm build:localhost`).

## 2026-11-08

- **feat(word): the Word task-pane add-in — search the Notees graph, insert live citations as Word fields, refresh them in place, and build a bibliography, all through the local `notees serve` bridge.** The lane ships as one record, newest slice first: **packaging** — the classic XML manifest (the shared-folder catalog does not accept unified manifests), the `/word/` dist layout the sync server serves (`NOTEES_WORD_ADDIN_DIR`), `${HOST}` resolution at build time, vendored Office.js (no CDN at runtime), and the sideload docs for Windows shared-folder, Word for the web admin-center, and Mac wef. **Badge** — the field-count badge with the host-capability fallback (read-only hosts count fields honestly instead of failing). **Style picker** — new insertions follow the picker; the explicit "Refresh all with this style" is the only thing that rewrites existing fields (a document-level switch never rewrites implicitly). **Bibliography** — insert-or-replace as one paragraph from the document's citation fields; a duplicated bibliography is reported, never silently left; the whole-paragraph replace semantics (sibling content in that paragraph is replaced) are documented and smoke-checked. **Refresh** — in-place re-render from each field's own embed, with skip-not-corrupt semantics: foreign (Zotero) and hand-corrupted fields are reported skipped and left untouched, a failed render keeps the existing text, and a bridge outage mid-run reports completed work only. **Search pane** — the debounced query → cite flow, including the stable-searchFn fix so a re-paired bridge is the one searched, and the pure engine unit-tested with injected seams. **Insert** — the citation lands as an `ADDIN notees.Citation` field at the selection (WordApi 1.5 OOXML insertion), with `CapabilityError` when the host lacks the field APIs. **OOXML + embed codec** — the pure field-code layer: the normative `{"citationId","nodeIds","styleId","locator"?}` / `{"styleId"}` embed JSON shapes, fldSimple generation, document scan, and the field-index → paragraph mapping. **Pane shell, settings, bridge client, scaffold** — the Vite+React shell with the pairing screen, the validated settings store (port + token persist across Word sessions), the typed fetch client over the bridge protocol (HTTP status surfaced so a wrong token reads rejected, not paired), and the repo scaffold with the vendored Office.js pin. Docs: `README.md` (build, `/word/` serving contract, all three sideload paths, pairing) and `docs/smoke-checklist.md` (the 15 host-only items vitest cannot cover, each checked by hand against a real Word build). Verification: full suite **132/132 green (14 files)** — `pnpm test` — with `pnpm typecheck` and `pnpm build` clean; the gate ran after every slice.
