# Feature status

Honesty, up front — every feature below is labeled. "Today" means it ships and works as described in these docs; "Designed" means the model is settled and the gesture specified, but the surface is not built yet. Where a feature has a full page in these docs, read it there; the rows below are the only documentation for the features without one.

| Favorites & recents (cross-device) | **Today**: the sidebar's Favorites and Recents sections, the star in the page header, and the palette's Recent section share one source. Favorites/recents are UI preferences — by the "device state is never an op" law they live in the sync server's per-user prefs store (`GET/PUT /api/me/prefs`, per account), not the operation log; every client keeps its derived DB semantics untouched. Offline, reads answer from the device-local cache and writes persist there, syncing on the next connection |
| Custom views as section tabs (cross-device) | **Today**: every collection-backed section (a page's backlinks, its unlinked mentions, a class's classed nodes) hosts custom views. The collection renders a tab bar — **Default** first (permanent, never closable — it renders the factory behavior) plus custom tabs in order — and a **+** opens the query builder: the composed filter persists verbatim as the view's stored query and refines the section's row set on top of its default query. Per tab: rename, reorder, delete; **Reset to default** removes every custom view of the section (emptying restores factory behavior — the default is derived, never stored). The tab bar stays visible whenever the section renders — a live filter emptying a tab keeps the chrome, with the empty line ("No matching rows.") inside the selected tab's body (the strip itself hides only when the page has no references at all, the system-section hide-when-empty ruling). Views are per-user prefs-channel state (`/api/me/nodes/:nodeId/sections/:sectionKey/views`, the favorites/recents ruling); offline they are read-only |
