The normative spec behind the model lives in [packages/protocol/SCHEMA.md](../packages/protocol/SCHEMA.md); the ideas are in [philosophy.md](philosophy.md); what you can run today is in [usage.md](usage.md).

## Views follow the render state

View resolution is a pure function of two booleans and one edge — `is_class` (identity) × `parent_id` (placement) × `present_as_main` (render bit) decides what you see. There is no per-node view setting that could drift from what the node is ([philosophy.md](philosophy.md) on why that matters).

- **`page` → Page View.** A node presents as a page when it has no parent or when its render bit is set: header (icon, title), then the body block list, then system sections. A page's *content is its bullet tree* — there is no separate document body.
- **`block` → inline body, zoomable to Focused Block View.** A parented node with the render bit unset renders inline in its parent's body with block chrome; zoomed to center stage it is its content, its children, its backlinks, its properties — the outliner's "zoom into a bullet" from Logseq, generalized to any node.
- **`class` → Class View.** A node marked as a class (always a root) gets the **page view itself** — same chrome, same editable bullet-tree body (classes are containers and can hold child blocks) — plus class-relevant sections: the **extends** pills pinned to the card's top-left corner (the class's extensions, added with "＋ Add class extension" from a class-only selector; × removes an extension; cycles fail loud), the **classed nodes** table (the members — one column per property definition, table by default, outline/cards/kanban switchable; the class page's centerpiece, the Capacities/Tana lesson: instances are the page), the **property definitions** editor (one row per binding — drag to reorder, flag toggles for required/readonly/hide-when-empty, a config panel per row; expanded while empty, then collapsed like the page's Properties section), and the **templates** cards (bound instantiation templates — see below). The class's color and curated icon live in the header (one dot opens the picker; the swatch strip is gone). Below the body, the standard system sections plus **Extended by** (the subclasses, transitive — a backlink-class read). There is no separate description shelf: title-is-content means the class's title IS its description.

Two placement rules complete the picture. **Nested pages have the render bit set** — a child page opens in Page View and renders in its parent's dedicated **Child pages** (main-children) zone, never inline in the parent's body. And class nodes are always roots by construction — `is_class` implies no parent, enforced by a schema CHECK and a fail-loud move-guard. Classes may themselves have non-class children; the one tree rule left is that a class can never be a child.

Icons are *effective*, never required. The picker IS the v1 picker: the full emoji set and the full MDI sprite (7,447 names), All/Emojis/Icons tabs, a search across both vocabularies, and a device-local recents row — for pages and classes alike. A node displays its own icon when one is set; otherwise the first assigned class's icon (in class order, inherited through the class's `extends` chain); otherwise a display-time default — a shape glyph for classes, a document glyph for pages. The default is read-side only: nothing is written to the node until you pick an icon, and inline blocks stay iconless (their chrome is the bullet dot).

The web app renders Page View (interactive) and Class View (view resolution is the `is_class`/`parent_id`/`present_as_main` cascade); a block is reached by zooming its page, and the class catalog is inspectable via `notees class list` and `GET /api/classes` ([usage.md](usage.md)). Focused Block View as a standalone chrome remains designed.

## The outliner

The editor is a Logseq-style outliner: bullet points, and each bullet is a block is a node. The core contract:

| Gesture | Effect |
|---|---|
| `Enter` mid-text | **Splits the block at the caret** — the head stays, the tail moves to a new sibling right after. |
| `Enter` at the start | A new empty block **before** this one. |
| `Enter` at the end | A sibling after — unless the block has children, in which case the new block becomes their **first child**. |
| `Shift+Enter` | A `hard_break` — a line jump *inside* the block. The only break token in the grammar. |
| `Backspace` at the start of text | **Merges this block into the previous one** (previous sibling, or the parent when this is an only child — otherwise nothing). The unflushed draft rides along. |
| `Backspace` on an empty block with children | The children are **promoted** into the block's place, then the block is deleted. |
| `Delete` at the end | Merges a childless next sibling into this block. |
| Indent / outdent | `Tab` indents under the previous sibling; `Shift+Tab` outdents to the grandparent right after its parent. The outdent **behavior setting** (Settings → Editor) chooses Direct (only the block moves) or Logical (default — subsequent siblings follow under the outdented block, preserving category grouping). |
| Drag | Reorders among siblings (fractional positions + TreeCrdt — proven v1 machinery, ported). |
| Collapse / expand | View state only; children stay first-class nodes. |
| Prose mode | Bullets hidden, indents flattened — a **view transform, not content**. Collapse state is ignored, not cleared: every subtree renders and no collapse chevron shows; flip back and nothing changed. |
| `Ctrl/Cmd+C` with no selection | Copies that block's node link (`<origin>/<uuid>`) — same in a page title. With a text selection, the browser's text copy runs as usual. |
| `Ctrl/Cmd+V` holding a node link | Pastes the link as a **mention** at the caret (in a title: as the target's display text) instead of raw text; any other clipboard text pastes normally. Both directions toast a confirmation. |
| `@` with a selection | The selection survives: the node picker opens **with the selected text as its search query**, and confirming (or creating) replaces the selection with the link. `Ctrl/Cmd+Enter` on a row inserts the link with the selected text kept as a custom label; Esc hands the selection back untouched. |
| Right-click a node link | A context menu: **Open** / **Open in sidebar**, **Edit link…** (retarget the link, set or edit an optional custom label), **Remove link** (unlink, keeping the text — or the custom label when one is set), **Delete link** (removes the link from the block entirely). |
| `Alt+Shift+↑` / `↓` in a block | **Moves the block** among its siblings — reorder without dragging. One move per press; the caret stays put. |
| `Ctrl+.` on a block, `Ctrl+Alt+←` / `→` | **Fold / unfold the focused block's subtree** (session view state). `Ctrl+.` toggles; the Ctrl+Alt chords go one direction each. (Alt+←/→ are Back/Forward — see below.) |
| `Shift+click` / `Ctrl+click` a block row, or drag over rows | **Multi-select** blocks. Shift+click extends a range from the anchor, Ctrl/Cmd+click toggles one row, press-and-drag arches over rows. A floating action bar offers the group ops — bulk class assign/unassign, bulk tag, bulk move to a page, bulk delete (confirmed) — one write per block. Esc or clicking elsewhere clears. |
| Click the muted "+ Add block" row at the page's end (always present) | The **ghost block** (v1 behavior, §34.106-refined): the page root trails exactly one muted "+ Add block" row as the last sibling of the main level — including on an empty body; display-only until the click, which creates a real empty block at the end and focuses it. It is the sole add affordance (no separate add button), and its bullet reads faint — never at a real bullet's weight. In prose mode it stays, bullet hidden like every prose bullet; cards mode has none. |
| `Alt+←` / `Alt+→` | **Back / Forward** through the pages you opened — the app's own history stack, the same one deep links ride. |
| `Ctrl/Cmd+N`, `Ctrl/Cmd+,`, `Ctrl/Cmd+\` | **New page** (created and opened), **Settings**, **toggle the sidebar**. Every global chord yields to text fields. |

Long-form writing emerges from nesting bullets, not from a document mode. That is a deliberate bet — the confident statement is: structure you got for free beats structure you typed as metadata.

Blocks are first-class storage but second-class display. Display defaults keep them quiet: backlinks aggregate mentions per containing page, the graph collapses children, search ranks by relevance and recency with block hits labeled by their containing page (the sidebar search field and the palette's Content section), and queries default to root scope. When a bullet matters enough to stand alone, you promote it — see [Promotion and demotion](#promotion-and-demotion).

**Assets are content.** An `asset_ref` token in a block renders instead of merely naming the file: image-like bytes show an inline preview (click opens the fullscreen lightbox, with download), anything else a filename-and-size chip (click downloads). A block whose entire content is one asset renders it full-bleed. The bytes ride the content-addressed asset store; a reference whose asset no longer exists shows a dashed placeholder with the raw id — never a silent hole.

**The editor.** The full outliner interaction set — the text core (typing with debounced saves, the editable filling the row so clicking anywhere places the caret, Enter placing a new sibling right after the current block, Shift+Enter hard breaks, Backspace delete, Tab / Shift+Tab reparenting via `object.move` with fractional sibling-midpoint ordering; the editing block's bullet carries the accent highlight — the engaged-row signal at a glance), **marks editing** (structural edits preserve untouched runs; selection toolbar + Ctrl/Cmd+B/I/Shift+X + `**`-wrap), **node-link clipboard** (Ctrl/Cmd+C on a block or page title with no selection copies `<origin>/<uuid>`; pasting that link — or a bare uuid — splices a mention at the caret, both with a toast confirmation), **link authoring from selection** (typing `@` over selected text opens the picker with that text as the query; the pick replaces the selection, Ctrl/Cmd+Enter keeps it as a custom label), **node-link context menu** (right-click a link: edit destination + custom label, remove the link keeping the text, or delete it outright), **code blocks** (`/code` converts the block — the sentence you wrote becomes the code, the typed argument is the language hint; a code block edits in place through a CodeTextarea surface: the language badge stays, typing writes the token's text on the standard debounced path, Esc/blur hands back to read mode), **collapse** (chevron per block, hidden at rest and revealed hovering the bullet gutter — resting rows stay clean, session-local, plus the `Ctrl+.` / `Ctrl+Alt+←/→` fold chords on the focused block), **block multi-selection** (shift+click range, Ctrl/Cmd+click toggle, drag-over rows — the floating action bar applies class assign/unassign, tags, moves, and confirmed deletes across the set), **the ghost block** (v1 behavior, §34.106-refined: the page root trails exactly one muted "+ Add block" row as the last sibling of the main level — even on an empty body, in outline and prose; one click creates a real empty block at the end and focuses it; the bullet reads faint, and prose drops it like every prose bullet), **prose mode** (a pure view transform: bullets hidden, indents flattened; collapse state ignored — every subtree renders and no chevron shows, the session collapse set untouched for the return to outline), **drag reorder** (dnd-kit, deep-drop to reparent, guard-railed against cycles and CHECK violations), **block moves without dragging** (`Alt+Shift+↑/↓`), and **global undo/redo** (see below). Still designed: editing-through-embeds and the tablet shell.

## Popups — one dismissal convention

Every popup in the app — pickers, menus, popovers, the suggestion popups — follows one convention: **Esc closes it, and clicking outside closes it.** Pressing *inside* a popup never dismisses it (only the pick itself does), and dialogs close on backdrop click the same way.

## Undo and redo — the session journal

Notees keeps one authority — the immutable operation log — and the undo journal is a **client convenience on top of it**, not a second history: every edit you make is an op in the log, and undo works by composing **existing ops in reverse** (an update restores the captured prior values, a create becomes a soft delete, a delete becomes a restore, a move returns to the prior parent and sibling position). Nothing about undo changes the wire; an undone edit syncs like any other edit.

The journal is **session-local and per-tab**:

- It records only what **this tab** wrote. Another device's (or another tab's) edits apply to your view but never enter your journal — you cannot undo what you did not write.
- It lives in memory: a reload starts empty, and the durable unpushed backlog replays without re-entering it.
- It is **bounded** (200 entries) and typing coalesces: contiguous edits to one block inside a short window are **one** undo step, so undoing typing is paragraph-grained — press once, the whole run of typing comes back.

**What undo covers:** everything structural — creating and deleting blocks and pages, text edits (title renames included), moves and indents, class/tag assigns and unassigns, property edits, class-property binding changes, extends changes, colors and icons. The **topbar** carries the journal too: an **undo and redo button** beside the calendar toggle — disabled when there is nothing to (re)apply, titled with the exact next step ("Undo edit text") — and the undo button's **chevron opens the history menu**, a browsable list of everything this tab did (newest first, each row its label and time). Clicking a row **jumps to it**: the affected node opens (for text entries that is plain navigation — the journal cannot restore a past caret, and it doesn't pretend to); rows whose nodes no longer exist list disabled. The same menu opens on **Ctrl/Cmd+Shift+H**. Two honesty limits: a **permanent** delete is data loss and is not undoable, and deleting a **class** tombstones its memberships, so it is not undoable either.

**The keystroke rule:** Ctrl/Cmd+Z undoes, Ctrl/Cmd+Shift+Z (or Ctrl+Y) redoes. While a text field — including the outliner editor — owns the focus, the keystroke stays **text-scoped**: the editor keeps its native text behavior and the global journal stays out of the way. Everything outside text editing — structural gestures, property edits, deletes, moves, renames — is one journal step, reachable the moment focus leaves the editor. There is deliberately no cross-buffer guessing: the editor's local text undo is text-scoped, the journal is gesture-scoped, and the two never fight over a keystroke.

## Offline work — and the backend-down ladder

Reads always answer from the device-local store and writes persist there, syncing when a connection comes back — offline is the default state of the world, not an error state. When the sync backend goes unreachable mid-session, the app escalates one explicit rung at a time:

1. **Banner** — "Backend unreachable — working locally until it recovers." Dismissible; the app keeps working off the local projection of your data.
2. **Lock** — dismissing the banner while the backend is still down swaps to a full-screen lock, because past the grace period new edits would only pile into this browser's storage, invisible to your other devices. The lock carries the escape hatch — **Continue anyway** — beside an honest statement of what continued local work risks: the local-only backlog is lost if this site's data is cleared before sync resumes, and if the same content changes elsewhere in the meantime, the conflict resolves by last-writer-wins, not by what you meant.
3. **Persistent banner** — escaping the lock returns to the shell under a non-dismissible banner until the backend recovers, so a degraded session can never look clean.

Recovery resets the ladder: the next outage starts again at the dismissible banner.

**The sync dot is a door, not a lamp.** The dot in the top bar (idle / syncing / backlog / error) is clickable: it opens a details panel with the engine state, the pending/failed/quarantined/parked backlog counts, the server seq, and the last error — plus two actions on the same surface. **Resync now** forces one push-then-pull cycle against the relay (the same cycle the automatic path runs, on demand). **Conflicts** lists the semantic conflicts this session has seen (concurrent moves, edit-vs-delete, class and property clashes — the CRDT merge stays authoritative; the list is the "the log picked a winner, but you should know" record), newest first with the node's name, the clash type, and both sides' op counts.

## System sections — and the lazy-loading contract

Pages come with predefined sections that are **named system queries** over the query runtime, not bespoke UI: **linked references**, **references** (outgoing), **unlinked references**, **child pages**, **classed nodes**, and **extended-by**. They are fixtures like any op type, and the section registry becomes plugin-extensible later.

The rules, all of them load-bearing for performance:

- **Collapsed by default, and a collapsed section runs no query at all.** Nothing loads until the first expand.
- **Count badges come only from materialized counts** (`node_stats.backlink_count`) — the badge renders unconditionally and is exempt from the contract because reading it is reading a stored number, not running a query.
- **Unlinked mentions shows no eager count.** Computing it *is* the expensive query — it is a full-text search for the page's literal name across the workspace, excluding blocks that already link to the page. Pages only; blocks do not get this section.
- **Results cache** per section until an invalidating notification lands (a content, class, or property edge change).
- **Blocks get backlinks in place.** A block with backlinks shows a count badge in the right gutter; toggling it expands the linked-references query scoped to that block, inline beneath it — the query runs on first toggle, per the contract.

Backlinks list *actual* links — but the backlinks view can be narrowed by facets over inherited links: Jane's backlinks filtered to `refset ∋ ACME` shows only the Jane-mentions made in the context of ACME, even when the ACME link lives on a parent block (Logseq's linked-references filtering, generalized — see [philosophy.md](philosophy.md#what-we-took--and-the-wounds-that-became-our-rules)).

**The web client renders the page-level sections** — backlinks (badge from the materialized `node_stats.backlink_count`) and unlinked mentions (pages only, no eager count: an FTS over the page's name excluding already-linked sources, with per-row Promote/Ignore), plus child pages — with the two references behind one tab strip in the old slot between Child pages and Activity: **both tabs always show** (an empty tab says so), a tab's query runs on first activation only, and the tabbed panels render headerless (the tab is the section header — no duplicated tabs-plus-headers chrome). An opened tab re-runs its query when a notification lands and caches until then. The right rail's References panel is the incoming direction wearing the same name. The block-level backlink gutter renders too: any block row with backlinks shows the count toggle in the right gutter, and expanding it runs the same backlinks query scoped to that block, rendered inline beneath the row. **Bound verbs surface in both**: a property value over a bound verb schema (the create-and-bind gesture's object/multi property, the designed targeted path) projects into the edge index with the schema id as its verb, so the target's backlinks — page section and block gutter alike — list the source with a quiet pill naming the schema ("supports", "cites"). The verb-mark-on-a-word itself stays targetless (typed-link target resolution is the deferred design) — the pill names the designed path, never a heuristic guess. The classed-nodes section rides with the Class View.

The **Activity** feed closes the page-bottom stack: a workspace-level section, honest about what the local projection derives. *Recently created* runs one workspace-wide query (the compiler's `entire_workspace` scope, newest first — blocks included) **only while expanded** — collapsed, the section executes no query at all, and it carries no eager badge (no materialized activity count exists, so like unlinked references it shows none); *Recently edited* lists pages and classes whose updated time postdates their creation, and says so — a block's edit time surfaces on its page, not here. It stays off embedded feed entries, which already sit on aggregation surfaces.

## Long lists — one pagination convention

Every list that can grow without a bound windows the same way:

- **A session-local window, grown by an honest affordance.** The first 100 rows render; a **"Show more (N remaining)"** button at the list's end grows the window by another 100. The count names what is hidden — a window never drops data silently, and the button is a real, keyboard-focusable control.
- **Sorting or filtering resets the window.** A resort re-narrows to the first 100 instead of inheriting a grown window.
- **Counts, badges, and exports always read the FULL set.** Hub totals, kanban column counts, reference-group counts, and every export (the table's CSV whole-view download among them) cover everything — the window is display-only. The table's header checkbox selects exactly what is loaded, and says so: **"Select all loaded rows."**
- **Where it applies:** every node-collection view — outline lists and grouped sections, cards, kanban columns (each column its own window), tables, and read-only page trees (the child-pages projection, the reference sections).
- **Where it deliberately does not:** the **editable outliner tree** — a window could hide the block you just created; the editor's collapse chrome is the existing answer. The **command palette and the pickers** stay bounded-scroll surfaces narrowed by typing: their lists live inside a fixed-height scroller and the keyboard cycles the filtered set, so a Show-more would fight the search idiom.
- **The feeds keep their own honest patterns.** The journal windows around today with scroll sentinels (prepends compensate your scroll position so the viewport stays put), search pages through a cursor ("Load more results"), saved queries window at 200 rows with "N more — load more", and the Activity feed is a bounded summary by design (20 created / 10 edited — a digest, not an archive).

## Mentions, chips, and typed links — marks on words

All three are tokens in the same flat content stream ([SCHEMA.md grammar](../packages/protocol/SCHEMA.md)), and all three obey the same rule: **nothing is inserted; the word you wrote is the annotation.**

- **Mention** — a pill. Stores the target's id plus the captured surface form; rendering resolves the *current* name, so renaming a node updates every mention for free. An optional `displayText` overrides per-link ("the Republic"). A broken target renders the raw id — never silent retargeting — and the link-edit modal offers the honest fix: **create the page with that exact id**, so the mention heals in place (no retarget write). In the editor the pill is an **atom** — one caret unit with the read-mode underline look: arrows select it when the caret reaches it (selected = primary-colored text on a faint primary tint inside a focus-ring outline), clicking it selects (a second click hands the caret back, double-click opens), Backspace/Delete deletes it whole (selected or adjacent), right-click edits/unlinks/deletes it in every view mode.
- **Class chip** — render-only, by decision. Inserting a chip does not assign the class; it references the class node and renders its current name. Assignment is a separate gesture, and a lint may suggest it ("chip present, node not classed — assign?"). Suggestion, never enforcement. In the editor the chip is an **atom** like a mention pill (the v1 wavy underline): the label re-resolves at build time — the token stores no text — and editing around it never silently drops it; arrows select it, Backspace/Delete deletes it whole, double-click opens the class. A title that IS only a chip excerpts to the resolved class name (breadcrumbs included).
- **Typed link** — the distinctive one. You write the sentence naturally ("argument X *contradicts* argument Y"); the verb is a **mark on the word**, with an optional target and token metadata such as a locator. Rendering is a subtle colored underline with a hover card, plus a global "show types" overlay (off by default in reading mode). Lifecycle is honest: delete the word and the mark dies with it — the graph stops claiming what the sentence no longer claims. The verb is a property-schema reference *or a bare free string*; when the verb you want doesn't exist yet, **create-and-bind** makes the schema at capture time (the Tana lesson: schema-at-capture or the feature dies in setup). The adorned mention pill survives only as the escape hatch for when there is no natural verb ("see <<Y>>").

**Record, don't resolve.** Capture records candidate target spans as an ordered list — implemented as the `targetNodeId`s of the block's mention tokens, nearest-first by prose distance from the mark, capped at 8 (the flat grammar has no token ids; this interpretation is recorded in SCHEMA.md). No scoring, no filtering. Target resolution stays deferred, designed against real captured data.

Citations are the canonical dogfood: a `cites` verb with the locator auto-filled from the current PDF selection, grouped backlinks by verb, bibliography views — the research environment.

**The web editor:** `@` opens the node picker (mentions) with the caret already in its search field, scoped by **Main/Blocks tabs**: Main (the default) searches pages, classes, and other document-chrome nodes through the relevance-ranked index; Blocks narrows the same search to inline child blocks, each row labeled with its containing page. The no-match row **creates the page** (title = the query; `class:Name ` typed first narrows candidates to that class and the create lands inside it). When the filter is a **source subclass** the create row instead opens the citation dialog — type, title, authors, year, DOI — authoring a properly classed source with linked person nodes; an **agent** filter (person/organization) opens the given/family-name split. Typed dates offer **"Link to daily page: …"** (or "Create …" when the journal page doesn't exist yet). `#` opens tag vocabulary (**Enter assigns the highlighted tag, creating it if missing**), `+` picks existing classes the same way — and both are **multi-select**: clicking rows accumulates a checked set (picked rows ride the top of the list), the **Apply** button or `Ctrl/Cmd+Enter` assigns the whole set in one gesture, while a plain Enter keeps the fast single-assign path. Filter prefixes refine any of these pickers: **`daily:`** lists (or narrows to) day-precision journal pages, and the booleans **`is_daily:` / `is_page:` / `is_class:`** (true/false) split the pool — the tokens never become part of the search text or a created title. A selection + Cmd/Ctrl+K (or the toolbar verb button) opens the verb popover: the verb matches the workspace's property schemas live — an exact name hit offers **"Bind to property …"** (the mark carries `verb: { propertySchemaId }`, renders the schema's name, and projects into the edge index by schema id), and a name nobody has used yet offers **"Create property '…' and bind"** — the schema is authored at capture (typed `object`, multi, no class filter) and the mark binds to it in the same gesture. The plain **Link** submit keeps the free-string verb, and right-clicking an existing typed-link word reopens the verb field (same rows) to rebind or edit the locator. Rendering resolves names everywhere. Still designed: locator autofill from PDF selections and target resolution.

## Templates — class-bound instantiation

A template is a node, not a new kind: the `template` class says "this node's subtree is a reusable body". Binding is a property edge (the class's **Templates** cards); instantiation is a client-side clone over ordinary single-node ops — the copy is stamped with a `generated-from` provenance link, and provenance is one-way: editing a copy never writes back, and unbinding never touches copies. The create surfaces stay unfiltered: one class-filtered picker — the class's own template bind — instead of filter plumbing everywhere; template *choice* happens at the moment of creation, Capacities-style.

Binding/unbinding lives on the class page (template cards), and instantiation rides the object-create flows that offer a bound template (calendar quick-create among them). `/template` instantiates at the caret from a flat, unfiltered list (the typed remainder filters it — commands match on the first word, the rest is the argument); the gallery (Templates section → Browse gallery) is the browse surface with keyboard create-with-template (type to filter, arrows, **Enter** uses the highlighted template); **{{…}} variables** substitute at apply time — editable static rows + read-only computed dynamic rows (`today`/`time`/`datetime`/`current_page`, local time — never UTC) — and apply-to-existing grafts onto a picked node without overwriting content it already carries, skipping nodes already generated from that template. Not shipped: a global create-with-template chord (Capacities' Ctrl/Cmd+U analog — the keymap is the App shell's register).

## Whiteboards — spatial views of subtrees

A whiteboard is a node classed `whiteboard`; the `whiteboard` content token carries its geometry. The model, precisely:

- **Cards are child blocks.** Full content grammar, backlinks, search indexing, focused view, classing — a card is a block that happens to have `x, y, w, h`. The tree holds content; the token holds geometry, keyed by node id.
- **Shapes are geometry only.** Rectangles, circles, connectors, freehand strokes — layout-token data with no identity and no node overhead.
- **Semantic text lives in cards, not shape labels.** A label is chrome; text that matters to the graph gets a card. A lint may suggest promoting a label to a card — the design law's usual enforcement.
- **Dragging a card is a layout update** — debounced and coalesced into ordinary content ops. No per-mousemove op spam, no new sync primitive.
- **One node, three views.** The same children render spatially (the whiteboard), as an outline (the outliner), or focused (Focused Block View) — because they are the same nodes.

A whiteboard can live fullscreen (a parentless node) or embedded as an inline child of any block. Its cards index into search and the graph naturally — no separate "whiteboard content" that search can't see.

The `whiteboard` class is seeded in the catalog, the token is part of the normative grammar, and the web app renders the spatial canvas: a tool palette (select/move with box-select, card, sticky note, rectangle/ellipse/line/arrow, the pen/highlighter/eraser group, text, connector), one-shot draw tools that return to select after each gesture (the eraser stays armed until Esc), colors and stroke-width tiers over the selection, alignment/distribution helpers, a snap-to-grid toggle riding a world-anchored dot grid, a minimap with click-to-navigate, zoom controls (wheel, buttons, fit), and keyboard affordances (Delete removes the selection, arrows nudge, Shift+arrows step a grid, Esc exits the tool). The **pen** draws freehand strokes; the **highlighter** commits the layout schema's `highlight` marker — a translucent wide stroke in the marker color; the **eraser** drag-removes strokes and shapes near the pointer in one coalesced write (cards are graph nodes — they delete through their own chrome, never the eraser). A **right-click context menu** on any canvas object (cards, shapes, strokes) offers delete, bring-to-front/send-to-back (the geometry's z-order), and the color picker. Dragging any selected card moves the whole selection; every gesture coalesces to one content op. Embedded canvases keep the full toolset minus pan/zoom (scroll priority). Not shipped: the remaining v1 breadth (15-shape set, sticky-ended connectors).

## Tables — cells are nodes
A table is a node classed `table`; the grid is a render projection of its subtree — the whiteboard pattern one level down:

- **Rows are child blocks; cells are each row's child blocks.** Every cell is an ordinary node — own UUID, full content grammar, backlinks, search indexing, classing, properties, the focused view. A cell that matters to the graph can be mentioned, classed, and zoomed via its bullet; the same children render as a grid, an outline, or focused, because they are the same nodes.
- **Linking to a cell is an ordinary mention.** The mention token stores the cell's id and resolves its current content at render — edit the cell and every reference follows. There is no separate "table content" that links can't reach.
- **The grid is a view, not a type.** The container's children render as a CSS grid: the column template comes from the first row's cell count; rows align by subgrid, so a ragged row shows a blank (fewer cells) or spills an extra column (more). Underneath, the tree is an ordinary outliner tree — Tab/Enter, drag, and the keyboard contract work inside cells unchanged.
- **Structure changes are ordinary creates.** `/table` scaffolds the container with one row of three empty cells (the typed argument is the column count — `/table 5`); hovering the table offers + Row / + Column, which append blocks. No new op, no wire token — every write is an `object.create` on ordinary nodes.

`/table` scaffolds at the caret and focuses the first cell; the container's hover toolbar appends rows/columns (**+ Row / + Column**) and deletes them (**− Row / − Column**, the inline-confirm pattern — the last row and the right-most column are the targets, and a deleted row's cells ride the ordinary subtree trash); cells edit inline through the standard block editor (the usual debounced save); embeds, the presentation deck, and the other read-only projections render the grid (the deck routes table-classed blocks through the same BlockRow grid branch — no flattening).

## The graph view — the workspace as a map

The graph view (the sidebar's Graph row, or the "Graph View" landing preference) renders the whole workspace as one interactive map: pages and classes are nodes, links are edges, a force-directed simulation runs off the main thread, and WebGL draws the result. The design law that keeps it readable: **blocks never render** — a link authored on a block rolls up to the page holding it, so the map shows the workspace's pages-and-classes skeleton (the journal chain hides by default; the toolbar toggles bring it — and class nodes, and each link family — back).

- **Families are honest.** Every edge names its kind — mention, property, parent, class membership — and the toolbar chips toggle each family independently. **Temporal** is the day's cousin of semantic: pages mentioned anywhere inside the same day page link together, hover names the day. Counts always read the full filtered set; the orphan toggle hides the unlinked.
- **Semantic links are content-proximity.** Two pages link semantically when a block mentions both; the weight is the shared-block count, the hover card names the blocks, and the sliders bound it (top-N per node, minimum weight) — display cuts only, nothing deleted. A context that mentions more than ten pages contributes no semantic links (an index page would otherwise spray a clique).
- **Layouts.** Force (the simulation, four presets), **Circle**, and **Tree** (concentric rings by parent depth — children always one ring out). Fixed layouts are deterministic; drag still rearranges.
- **Color groups.** Paint nodes by query — `class:book`, `prop:status:done`, a property name — each group a color, first match wins; the panel validates the query as you type. Settings persist per device.
- **Interaction is the outliner's.** Drag to pin, click to select, double-click to open, find jumps by name; positions persist per workspace. The minimap (corner) shows the whole map with your viewport — click it to travel. Reduced motion starts the layout paused. The right rail's local-graph card shows the open page's neighborhood (depth 1–3).

## Promotion and demotion

A bullet's prominence is soft state — one op flips it, and identity is preserved completely.

- **Block → page:** a bullet that outgrew its parent becomes a page in place. Same node, same id, every link intact; recents, search ranking, and the link dropdown pick it up automatically because they rank pages first — no re-filing, no copy.
- **Page → block:** demote a page back into the flow of another note; same in-place flip.
- **Declare a class:** create the node with the class identity (`notees object create --isClass` — a `class.create` op under the hood). The node becomes a root, leaves the content tree, and gains the Class View and configuration. Declaration-first: create classes, configure them, use them later or never.

The canonical story: a `meeting`-classed bullet in a daily note sits quietly for months. When it starts to matter, promote it — set its render bit (`--presentAsMain`), optionally nest it under the company page. Same node, same id, all links intact.

The flip is real from the CLI and object API (`notees object update <id> --presentAsMain` — see [usage.md](usage.md#a-real-session)) and from the editor: the block's context menu offers **Move to Pages** / **Move to content** (one undoable `object.update`). Because promotion flattens a block's content to plain text (title-is-content), Move to Pages asks first when the block carries rich tokens — the confirmation names what will flatten (mentions, typed links, attachments, …); whiteboards and queries survive untouched, and plain text promotes without asking. Recents/dropdown re-ranking and the class-declaration flow are designed.

## Presentation mode — the note is the deck

There is no slide editor and no slide objects: a presentation is a pure read of one page's subtree, split into slides by the same tree that holds the content (structure is the slide boundary — the content grammar has no heading or divider token, and needs none).

- **Slide 0 is the title slide** — the page's own text content, centered, with its icon and effective color.
- **Every page-zone child is a section slide.** A child in the parent's main-children zone (the Pages section — the render bit set) opens a slide: its own text is the slide title, its children are the slide body, nested blocks included.
- **Body children chunk into intro slides.** A run of inline-body children becomes one or more intro slides, closed greedily by a character budget and a block cap — short slides read large, dense slides compact, and a slide that still overflows scrolls inside itself instead of spilling off the stage.
- **A trailing image block pulls aside.** When the last body block of a slide is an image (an `asset` reference and nothing else), the slide splits — text left, image right; an image alone centers at full size.
- **Embeds expand into the stream.** An embedded page's children splice into the deck as slides after the slide that references them — the live-subtree embed rule is untouched; expansion adds slides, replaces nothing.
- **Tables render as tables.** A table-classed body block rides the same BlockRow grid branch the embeds use — rows and cells render as a grid on the slide, not a flattened list.
- **Read-only but live.** The deck re-renders through the ordinary notify path as the note changes; nothing in a deck writes, and following a link exits the deck and opens the target. Session view-state only — the remembered slide index never touches the log, the store, or a device setting; it dies with the page session.
- **Gestures:** the "…" node menu → **Present**, the page header's context menu → **Present**, or Ctrl/Cmd+Alt+Enter (Ctrl+Alt+Enter — Capacities' Ctrl+Alt+P collides with the add-property chord). Arrows, Space, PageUp/PageDown navigate; the screen edges click through; Esc exits; a floating toolbar (previous, counter, next, exit) fades when the pointer rests and returns on any activity.

The overlay host is a UI-kit primitive (`PresentationOverlay`), sized for a second consumer — whiteboard fullscreen — later.

The deck builder, slide renderer, overlay, entry points, and session resume are in the web app, with full imagery support: asset tokens render as live images inside slide bodies (click → the lightbox), a trailing image block drives the split/full-bleed layouts, and the presented page's — or a section's — **cover** renders as imagery (the title slide's hero; the right column of a cover-split slide). Desktop-class surfaces only; a phone deck is deliberately out of scope (the mobile client is capture-first). Speaker notes and deck export stay parked — page Markdown export already covers "get the content out".

## Page chrome — banner, footer, and the right rail

The page's chrome follows the same law as everything else: **presentation state is device state, never content.** Nothing here writes an op except the explicit gestures, and every gesture is ordinary machinery (one `object.move`, one `contentAst` rewrite).

- **Covers.** The cover is HEADER CHROME, never a property row (the Properties panel suppresses it). The element is the v1 cover CARD: it sits in the header row's RIGHT column — collapsible via the chevron, ALWAYS rendered even when empty (collapsed to the strip by default; expanding reveals the dashed "Add cover" card, the image, or a placeholder naming a byte-less asset) — and accepts a dropped image file. A cover IS an ordinary **asset**-classed node (the dedicated `cover` class was dropped: it duplicated the property's meaning). The cover property value is the only authority; the asset wears a derived **Cover** badge in card views while any node's cover points at it, and cover assets list under the asset class's classed nodes. No cover value → the collapsed strip still shows (whiteboard pages and embedded feeds skip the element entirely). Imagery is LAZY: card lists render placeholders instantly and fetch bytes only as the viewport nears; clicking a cover — in the header card or any card view — opens the floating **lightbox** (download, fullscreen, Esc).
- **View modes stick — on this device.** The blocks triad (outline/prose/cards) persists per page, hub modes per hub, the classed-nodes mode per class, and the card cover layout once per device — all under `notees.settings.*`, none of it synced, none of it in the log. A persisted mode the surface no longer offers (kanban after its grouping select vanished) falls back to the surface default instead of resurrecting a dead switch.
- **The right rail is context.** Opening the right panel (the sidebar toggle, or shift+clicking into a peek card) shows the **Contents** and **References** sections of the page open in the main view, above the peek-card stack. The TOC is tree-derived, not token-derived — the grammar has no heading token, so sub-pages (the main-children zone) and short one-line blocks *are* the headings; the active entry highlights, click navigates. References are the linked-references query promoted into the rail, keeping the lazy-loading contract (a collapsed section runs no query; the badge reads the materialized count). The collapsed sections at the card bottom remain the small-viewport fallback.
- **The footer is a read.** Word count (title + the whole block tree) and Created/Updated stamps — formatted per the Settings date format — that open the corresponding day page through the ordinary ensure-chain read; table Created cells are the same day-page link. Pure projection, no new query surface.
- **Breadcrumbs edit the tree.** Hovering a crumb reveals its chevron — the crumb expands to make room for it, so the resting trail keeps even spacing; right-clicking opens the same menu: Open, Reassign parent… (a node picker), Remove parent (detach to the workspace root). A parentless page hides itself from the trail — there is no chain — and shows only a "+ Add parent" pill; class nodes show no breadcrumbs at all (classes are always roots — a parent is unrepresentable). Single-parent tree: every gesture is one `object.move`.
- **Unlinked mentions answer back.** Each row offers Promote — the literal name match in the source block rewrites into a mention, and the row honestly moves to Backlinks — and Ignore, a per-device dismissal that never touches the log.

**Deliberately not included:** per-class page layouts and wide/profile/encyclopedia geometry (a layout property would ride a class-bound select property — i.e. semantic state, so the decision stays open), index-card length constraints (title-is-content rejects them), and focus/zen mode (a display toggle, parked with its own gesture).

**Narrow screens.** Below the tablet breakpoint the chrome adapts without becoming a different app: the sidebar drawer gains a real surface above the page beneath it, sidebar rows and the shell's icon buttons grow to a 44px touch floor (the favorite star stays visible — there is no hover to reveal it), the topbar wordmark yields to the breadcrumbs, and page/card padding tightens. At phone widths an open right rail becomes a full-width bottom sheet (safe-area aware) instead of disappearing. A **floating action button** (the v1 quick-add) hovers over the content at these widths — tapping it opens the Quick Add modal (same flow as Ctrl/Cmd+Shift+N) — and tapping **outside the drawer dismisses it** (the press must land off the drawer and off the topbar, where the hamburger lives; desktop widths never dismiss).

## Query blocks and saved views

A query block is a **saved query as content**: the token carries the AST and a small persisted view record (`mode`, `title`, `isDefault` — SCHEMA.md's "The token view record"), so the query syncs like any text and every device renders the same choice of list or table. The results are a projection, not a snapshot: the block re-runs when the store changes (notification bursts coalesce — a burst costs at most one extra run, never one per envelope), the 200-row cap is a render window with an honest load-more, and Export downloads the current result set as Markdown.

The builder edits one representable subset — flat conditions, one sort, one aggregation — and **asks before it overwrites**: a query hand-written past that subset (OR/NOT, property conditions, multi-sort) opens on a read-only summary naming what would be lost, with an explicit "edit anyway" opt-in. Date fields accept `{today}`-style placeholders that resolve at run time, so "this week" means the week it is read, on any device, in any timezone.

The **Queries** hub gathers the workspace's saved views as tabs over one ordinary page (created on first save — its content *is* the views, so opening the page shows them as query blocks). The default view is a flag in the record, not a hardcoded choice; ad-hoc runs are session-only until named. Everything persists through the content update path — no view entity, no new op, device state stays out of the log.

## Day pages and the calendar

A date is a node, not a string (SCHEMA.md "Dates"), and the day page is the date's home in the UI. Two surfaces render it — the Calendar's day view (a dedicated aggregation surface) and the day page itself (an ordinary page, so it also appears in the journal feed, search, and everywhere else pages do) — and both read the *same* materialized state, never a bespoke query:

- **The day-page branch is read-model only.** A node whose id parses at day precision gets the **date header** (the weekday + Today flags above the title, the ISO week flag after it — day navigation itself rides the calendar popup and the Today surfaces, not a stepping bar) and, below its own content, **Tasks / Dated / Created** sections: the open-task partition (the tasks hub's exact write on the checkbox), the day node's existing backlink set minus date-chain sources and tasks, and a `createdAt` range query. All three honor the system-sections lazy contract — collapsed by default, nothing loads until the expand, hidden entirely when empty (the Created count is the one structured query, gated the same way unlinked mentions gates itself). **Month and year pages carry the same Created section** (created inside that month/year), and it defaults to the cards view with an outline switch. Embedded renders (the journal feed, the calendar's daily-note embed) skip both: they already sit on aggregation surfaces.
- **Reviewed is a property, not a protocol.** It is a plain boolean schema bound to the `day` class (self-healed at a fixed id, `hideWhenEmpty` so the panel stays quiet), written from the day page's Properties, read by the calendar grids as a small tint. It syncs like any property; clients that don't know it simply don't render it.
- **Calendar breadth rides the edge index.** Date refs and range ends fan out to the deterministic day node at projection time, so "objects dated this day" is one materialized backlink read — the month grid's range-aware dots (a day with dated objects but no note still shows) and the week agenda both derive from it, per the same exclusion rules as the Dated section. (Qualified-link metadata ranges edge from their start day only — the middle days stay undotted, the honest visibility of the current model.) The **week strip** under the grid is the selected day's seven days, same marks, click to select.
- **Recurrence is computed, not stored.** A repeating event is one node whose date value carries a small RRULE-lite rule (`daily`, `weekly`, `weekdays`, `monthly`, `yearly` — additive value metadata, SCHEMA.md "Recurrence"; no op, no wire change). Occurrences are virtual: the day view lists the event on every occurrence day with a ⟳ marker (one row per series — never phantom rows), the month grid dots each occurrence, and editing the event edits the series. The rule is authored from the calendar's quick-create bar or the Properties panel's date pill, and a date re-pick keeps it. A repeating task schedules on occurrence days and is never overdue — missed days roll forward to the next occurrence. **Completing an occurrence completes that day, not the series**: the day view's done-toggle on a repeating task records the date in the value's metadata (`completedOccurrences`), the occurrence renders struck-through on its day while every other occurrence stays open, and reopening removes just that date — no nodes are materialized, and the toggle off the occurrence context (the tasks hub) still means "the whole task".
- **Events are the calendar's base class; meetings and birthdays are events.** The seeded `event` class is the calendar family root — its single date property (whole-day per the dates law, no clock times) makes it quick-create eligible through the same date-binding rule as tasks. `meeting` extends `event` with a meeting-specific family (its own date plus text location/agenda); `birthday` extends `event` the other way — person-typed: a birthday links TO a person (`birthdayPerson`), the date still rides the event chain, and a person's page lists their birthdays through the ordinary backlinks section. Both are ordinary classed pages — queryable, template-able, mentionable; a date dots the month grid and lists the object in the day's Dated section like any dated object.
- **The tasks hub grows buckets, not a mode.** Overdue / Today / Upcoming / Unscheduled / Completed computes client-side from the effective Scheduled/Deadline/Status values — the same derived reads the table renders from — with the earliest-day rule so every open task lands in exactly one bucket and far-future work is never dropped. Device-collapse only; no query, no op.
- **Local midnight is the only "today".** Every today path (the shortcut, the calendar, the journal, the default-view landing) derives the day from local midnight; the UTC `.slice` pattern is banned by design.

All of the above is in the web app, and the system `event`/`meeting`/`birthday` classes are plain seeds — event is the calendar family root, meeting and birthday extend it; date-typed property families; existing workspaces materialize the families through the same idempotent ensure as the task family, and the calendar chips pick all three classes up through the generic date-binding rule. Note the browser reservation: Ctrl+Shift+T is "reopen closed tab" in most browsers, so the open-today chord fires only where the browser yields it (and as Cmd+Shift+T on macOS). The command palette answers the date affordances — `is_daily:` prefix, Date Pages section, formatted keywords — and the CLI verbs are `notees today` / `notees journal`. **Recurrence computes on read** — one node per series, virtual occurrences, RRULE-lite `metadata.repeat`; the picker authors None/Daily/Weekly/Weekdays/Monthly/Yearly — **with per-occurrence completion**: the day view's done-toggle records the date in `completedOccurrences`; one occurrence closes, the series stays open. Not shipped: the unreviewed-days queue.

## Properties — the panel and its contracts

The Properties section lists a node's effective property values: authored values win, class-bound defaults render dimmed until edited, and every write is an ordinary op. The main page layout (owner 2026-10-06, the Capacities-style mode) fills the whole content card with two columns on a continuous vertical divider: the properties sidebar rides the first column (1/3) — its own component (`PropertiesSidebar`: a property-name row + a value-cell row per property, name click → settings, right-click → the row actions; the value cells reuse the table's row components via a `bare` flag that hides their internal labels) — while the second column (2/3) is a three-row stack: the nodeview top bar pinned to the top (sidebar hamburger + classes pills left, view switcher + "…" right, over a full-width divider), the nodeview with auto height between the bars (the scrolling cell), and the footer pinned to the bottom as a divided section. The New/Search buttons and the workspace selector live in the app top bar only; the sidebar starts at Navigation. Secondary surfaces (sidebar peek cards, embedded renders, focus mode) keep the compact in-flow list (label-left table, collapsed by default). On top of those laws, the surface is hardened:

- **Broken stays visible.** A property value that points at a deleted node is not silently dropped: the pill shows the raw id in a dashed, muted chip, and restoring the target heals it — keep-value + render-broken is the graph-wide rule (SCHEMA.md "Broken references").
- **Values have history.** Right-click a property → **Value history…** renders the property's writes from the server-side operation log, newest first. Offline, the modal says so instead of guessing.
- **Types convert honestly.** The settings modal's **Convert…** changes a schema's type the one honest way: create the new schema, copy the values that map, list the ones that don't (dropped only with explicit confirmation), re-point the class bindings, delete the old schema.
- **Options carry color.** A select option can wear a data-palette color; its pill tints, and the settings modal edits it per option with one color dot.
- **Aliases are names.** The seeded `alias` property gives a page alternative names — searchable like the title, resolvable by exact match, and matched by unlinked references.
- **Text values are blocks.** A text property renders its values as editable blocks in the row — never repeated label entries. Enter on a multi-value property starts the next value (a sibling block registered as the next entry); Enter on a single-value property nests a child block under the value, whose children are its lines. The block is the value: it indexes, links, and deletes like any block.

## Exporting

Export is a projection of the graph into files — one-way by design (the log is the truth), engineered to preserve as much as possible.

- **The node is the export root.** A page (or a block, or several selected nodes) exports as Markdown with YAML frontmatter: the title derived from its content, its classes and properties (per-value qualifiers preserved). Its block tree becomes nested bullets in child order; child pages become their own files. Nothing is lost silently: cycles and depth cuts render as visible `[[uuid]]` references, rich text is Markdown-escaped, whiteboard layouts ride along as sidecar JSON inside zips.
- **The dialog is honest about scope.** Every format delivers real bytes: Markdown, HTML, Word, LaTeX, PDF (three layouts — Notes, Essay, Academic — on A4/Letter, rendered in the browser with a bundled open-license font; the heavy renderer loads only when you first ask for it), and the JSON archive — one versioned `notees-json-archive` document carrying every selected node's verbatim content tokens, class ids, property values, child order, and its mined mention/link/property edges; the highest-fidelity projection, the disaster-recovery artifact (CLI `notees export json` builds the same document). Markdown and PDF preview live as you toggle options; the others state plainly that preview is a Markdown/PDF affair.
- **Tables export what you see.** A table view's Export CSV downloads the current view — the visible columns, the full sorted result set, cells exactly as rendered, RFC-4180 quoting and a UTF-8 BOM so Excel reads it right. Checked rows surface two scoped actions: **Export selected CSV** (the same columns over just the checked rows) and **Export selected…** — the export modal's batch path scoped to exactly those nodes, any format. Cards and kanban collections carry the same machinery: a card checkbox accumulates a session selection, and the toolbar's **Export selected…** opens that same batch export — every view exports its selection identically.
- **Zips keep the graph contained.** Multi-file exports rewrite cross-page references to relative links (`[title](<file>.md)`) and name files `<title-slug>-<id8>.md` — human-readable, still identity-anchored (the id8 is a hash of the node id). An optional assets folder carries the bytes behind `asset` references as `assets/<name>-<hash8>.<ext>`. A manifest maps every file back to its node id.
- **The workspace exports whole.** One zip: every top-level and child page as its own file, the same conventions, plus everything assets. The system pages (the inbox; scratchpad pages from before the feature was retired) and the journal scaffolding (the year/month/day chain) stay out — exports are for your content, not the calendar's framework. The same projection is available headless — CLI `notees export markdown`, the shell's `exportMd`, and `GET /api/workspaces/:id/export.zip`.

## Sharing — read-only public links

Sharing a page mints a link, not a copy: the public view renders the page's *live* subtree at request time, and revocation or trashing the page ends it immediately.

- **The link is the whole contract.** No viewer accounts, no permissions matrix — possession of the unguessable URL is the capability. The modal says so in one honest line ("Anyone with the link can read this page"), and the threat posture lives in the docs, not in scare chrome: no directory listing (unknown, revoked, and expired links answer the identical 404), optional expiry, immediate revocation.
- **The viewer gets a document, not the app.** `GET /s/<token>` is one static HTML page — the title, the block tree as nested lists, the properties — same projection as the HTML export. No JavaScript, no app chrome, no write surface of any kind; a strict CSP, `no-store`, and a no-referrer policy ride along so the link leaks nothing (not even back to itself).
- **The manager is deliberately small.** Create → the URL appears with Copy; every live link lists with an inline two-step Revoke (never a bare danger click, never a confirm dialog for a reversible-in-spirit action — the row stays, dimmed, as history). No per-link analytics exist to show: the server does not track viewers, and the UI doesn't pretend otherwise.
- **What is parked.** The write-collaboration share variant (per-user shares, a Shares Inbox, edit access over a link) stays parked — the read-only public link is the whole sharing surface.
