# Pages

A page is a node in the standalone role — no parent, or parented but not embedded (`is_embedded = 0`, the standalone claim). This page covers what a page looks like and how it behaves: view resolution, chrome, presentation, and the page-level gestures (promote, convert, copy, divide, merge). The block role lives in [outliner.md](outliner.md), the class view in [classes.md](classes.md), and the collections a page hosts (list/cards/board) in [views.md](views.md).

## View resolution — pages and blocks

View resolution is a pure function of two booleans and one edge — `is_class` (classification) × `parent_id` (parent relationship) × `is_embedded` (embedding — whether the node's content belongs to its parent's body) decides what you see. The three concerns are independent: classification says what a node represents, the parent edge says which node it structurally belongs to, and the embedding flag says whether its content rides in the parent's body. There is no per-node view setting that could drift from what the node is ([philosophy.md](../philosophy.md) on why that matters).

- **`page` → Page View.** A node presents as a page when it has no parent or when it is not embedded in its parent (`is_embedded = 0`, the standalone claim): header (the Capacities action row, the icon + title, the subtitle, then the tags row), then the body block list, then system sections. A page's *content is its bullet tree* — there is no separate document body. The header title is the page node's own content rendered as a bullet-less block row — the full block editor (mentions, external links, marks, the slash menu) in display and edit mode; Enter commits and leaves the title instead of creating a body block, and the structural delete/merge gestures never touch the page itself.
- **`block` → inline body, zoomable to Focused Block View.** A parented node with the embedding flag set (the default) renders inline in its parent's body with block chrome; zoomed to center stage it is its content, its children, its backlinks, its properties — the outliner's "zoom into a bullet" from Logseq, generalized to any node.
- **`class` → Class View.** A node marked as a class gets the page view itself plus class-relevant sections — the full class-view description lives in [classes.md](classes.md).

Two placement rules complete the picture. **Nested pages are standalone under their parent** (`is_embedded = 0`) — a child page opens in Page View and renders in its parent's dedicated **Child pages** zone, never inline in the parent's body; its content is not part of the parent's body. And class nodes are always roots by construction — `is_class` implies no parent, enforced by a schema CHECK and a fail-loud move-guard (see [classes.md](classes.md)).

A third rule is presentational, and it is opt-in: **a link marked embedded** (the Edit-link dialog's "Embed this link" toggle — a manual per-link choice, default off) **whose block carries only that link presents the target in its place** — the referenced node's content renders inline in the block's seat (transclusion-style), regardless of whether the referenced node is a page or a block. An unmarked link is an ordinary mention chip even when it is the block's whole content; a link mixed with other content stays an ordinary chip either way. The embed token's rendering is documented in [links.md](links.md).

Icons are *effective*, never required. The picker IS the full picker: the full emoji set and the full MDI sprite (7,447 names), All/Emojis/Icons tabs, a search across both vocabularies, and a device-local recents row — for pages and classes alike. A node displays its own icon when one is set; otherwise the first assigned class's icon (in class order, inherited through the class's `extends` chain); otherwise a display-time default — a shape glyph for classes, a document glyph for pages. The default is read-side only: nothing is written to the node until you pick an icon, and inline blocks stay iconless (their chrome is the bullet dot). The page **header** is stricter (the Capacities ruling): the icon element renders ONLY when an icon is defined — own or class-contributed; the generic default never shows there, and there is no empty placeholder. The header's quiet **action row** above the title carries the affordances instead — **Add icon** (the full picker, anchored at the button), **Add description** (the subtitle editor), **Add aliases** (the shared alias picker) — every action retiring once its gap is filled (an icon defined, a subtitle set, an alias linked; all three set and the whole row is gone) — and the **description** subtitle under the title hides the same way until one is set (click it to edit; an empty commit clears). Day pages skip the row and the subtitle (the date-header contract, [calendar.md](calendar.md)).

The web app renders Page View (interactive) and Class View (view resolution is the `is_class`/`parent_id`/`present_as_main` cascade); a block is reached by zooming its page, and the class catalog is inspectable via `notees class list` and `GET /api/classes` (see [cli.md](../cli.md) and [api.md](../api.md)). Focused Block View as a standalone chrome remains designed ([feature-status.md](../feature-status.md)).

## The app shell — sidebar, top bar, and popups

**Page list** — every active page, the Pages hub (creation is not duplicated there: a new page is the top bar's **New** flow — the "No class" pick —, the palette's New-page command, or **Ctrl/Cmd+N**; a local-first write: applied to the local SQLite projection immediately, pushed to the relay in the background). A listed page expands its **subpage tree** — child pages nest under their parent — but its **inline body blocks never surface here**: the hub is a pages surface, not an outliner (the Whiteboards and Inbox hubs scope the same way). Row chrome is scoped to identity too — the class pills stay, per-row **properties** and **tags** don't render on hub rows (open the page for its metadata). The top bar carries the workspace selector, a **New** button (picks a class — single-pick, one untitled page of that class, created and opened on the pick; "create a person", "create a project"), a search button ([search.md](search.md)), and — on the right side — the in-app **Back/Forward arrows** (the pages-and-hubs history you built this session; **Alt+←/→** rides the same stack, and the arrows disable at its ends because the browser's own history reaches beyond the app), the **focus-mode** bracket button (below), and — while a node is open — the **layout button**: it flips the current node between the **sidebar layout** (the properties panel rides the first column) and the in-flow **sections** layout, session-only (the icon names the active mode; nothing is stored). **Today** leads the sidebar's Navigation rows (today's day page, ensured on demand — [calendar.md](calendar.md)) — the sidebar itself starts with Navigation (Today, Journal, Calendar, Inbox, Pages, Classes, Whiteboards, Tasks, Assets, Graph). The sidebar also carries the **Favorites** and **Recents** sections: **Favorites always renders — empty, it says "No favorites yet"** — and both lists show the same row UI (icon + title, class flag), with Favorites **drag-sortable** (drag a row to reorder; the order follows your account across devices). Star a page from its header star, any node context menu, or the row's own star (on hover the star renders in-flow and displaces the row content — the class flag chip — instead of overlaying it). The lists follow your account across devices (server-side per-user prefs), falling back to this device's copy while offline ([offline-and-sync.md](offline-and-sync.md)). Row titles render as **plain text**: a title's mentions, class chips and styling flatten into the title's own words and a link reduces to its label (no URLs in a row), so the row is a single click target — **Shift+click** peeks the node in the right sidebar — and a right-click anywhere on it opens the row's own menu. The sidebar's foot is the **user profile** (avatar + name + email): a sync-state **badge rides the avatar's corner** (green idle, blue pulsing syncing, amber backlog, red error — the full sync-state model is [offline-and-sync.md](offline-and-sync.md)'s) and the click opens the **account popup** — the identity header (avatar, name, email), a **Sync** entry (its caption names the live state: "up to date", "N waiting", "error") opening the sync details modal, **Shares** ([sharing.md](sharing.md)) and **Trash** (the trash hub: soft-trashed subtrees, newest deletion first, each row with **Restore** and a confirmation-gated **Delete permanently** — restore is the same first-class `object.restore` op the undo journal and the CLI use), **Settings** (also one click from the gear beside the profile), **Admin settings** (admin accounts only — the workspace settings, plugins tab, [plugins.md](plugins.md)), and **Sign out**.

Every popup in the app — pickers, menus, popovers, the suggestion popups — follows one convention: **Esc closes it, and clicking outside closes it.** Pressing *inside* a popup never dismisses it (only the pick itself does), and dialogs close on backdrop click the same way. Every sidebar popup — the account popup, the workspace switcher, the row menus — closes on Escape or a press outside itself.

## Page view

The page header and its block tree, rendered from content tokens: the header carries a quiet **action row** above the title: **Add icon** opens the full icon+color picker, **Add description** edits the one-line subtitle that rides under the title (a `description` wire node field, hidden while empty), **Add aliases** opens the shared alias picker — each action retiring once set (all three filled, the row disappears) — and the header **icon element shows only when an icon is defined** (own or a class's; no generic default, no placeholder). The **title row is one whole-row click target** — a click anywhere on it, the words or the empty space beside them, swaps in the block editor (the block row's click-to-edit contract: the title IS a bullet-less block row); **Shift+click peeks the page in the right sidebar** instead (the bullet gesture's header twin); the header icon keeps its own click (the picker), the block-bullet analog. Then the block tree: text marks (bold/italic/strike/highlight/code), mentions and class chips resolved to current names, quotes, external links, math (plain-code fallback until KaTeX), `hard_break`; a code block renders as a mono block with its language badge and edits in place (click it — the CodeTextarea surface writes the token's text on the usual debounced path); query tokens run their saved query and render the results (edit the query's JSON only when you mean it — a malformed query renders an "invalid query" placeholder rather than guessing — the query model is [queries.md](queries.md)'s); whiteboard tokens open the spatial canvas ([whiteboards.md](whiteboards.md)); and embed and asset tokens render per [links.md](links.md). Class pills (the page's corner cluster and every block row's right-hand column) ×-remove a membership — on every row, editable and read-only reference rows alike (the backlinks/unlinked rows answer class edits — ×, "+", drag-sort — only date-chain nodes render static) — except the system/journal classes (the class anchor, year/month/day), which are identity-bearing: their pill shows a lock instead, and the click explains instead of removing. In the block row the column's "+ Add class" ghost pill rides at the START of the pill cluster and reveals with the classes-list hover (or keyboard focus), reserving no space at rest — the hidden pill collapses entirely and, because the row-end group is right-pinned, the reveal grows leftward over the text column: the class pills and the backlink toggle never move.

## Focus mode

Focus mode hides chrome elements, it doesn't re-space the page. The top bar's **focus-mode bracket button** (also the command palette's **Focus mode** action and **Ctrl/Cmd+Alt+F**) dims the shell chrome — top bar, sidebars — to a whisper while the page stays full strength, keeping its normal panelled layout and spacing; Esc exits. Focus mode is NOT a secondary surface: it keeps the panelled layout — the normal spacing — and simply hides the chrome: both side panels, the top bar's panel toggles + classes pills, the in-flow properties, and the header chrome steps aside; the content column caps at the comfortable 46rem measure and centers inside the card (the compact layout's spacing-6 lateral padding rides inside the cap — full-bleed read worse than the old centered column), while the nodeview top bar still spans the card so the view switcher and the node menu stay (the page is still a working surface). The condensed layer's chrome stays visible in focus mode — stretching is the reading act, not metadata chrome ([outliner.md](outliner.md)).

## Page chrome — what sticks and where

The page's surroundings, and what remembers what. The law underneath: presentation state is device state, never content — nothing here writes an op except the explicit gestures, and every gesture is ordinary machinery (one `object.move`, one `contentAst` rewrite).

- **View modes stick (this device) — the page's own triad.** The outline/prose/cards triad on a page persists per page under `notees.settings.*`: once chosen, it survives reloads; storage is device-local, another device does not see it, and none of it ever enters the operation log. If a saved mode no longer applies (e.g. cards on a surface that no longer offers it), the surface falls back to its default. The collection modes — every hub's mode, the classed-nodes mode, the cards cover position and flow — follow the same law; their ruling lives with the views in [views.md](views.md#view-modes-stick-this-device).
- **Appearance sticks (this device).** The account popup's **Settings** entry (or **Ctrl/Cmd+,**) opens the full settings page at `/settings/<section>` (appearance, editor, general, sync, account, security, support, about; unknown sections land on appearance), and the palette's **Toggle theme** command flips light↔dark in one gesture from anywhere. Settings → Appearance holds the theme — one 4-option control: Light, Dark, OLED deep-black, or Auto (follows the OS) — the accent color (five curated swatches — Margin Green by default; no custom wheel), and the **UI font**: bundled (Instrument Sans for chrome, Newsreader for reading text, and JetBrains Mono for data — shipped with the app, no CDN) or the platform's own system stack. Applied pre-paint via a `data-` attribute, remembered device-locally like the view modes, never in the operation log.
- **Covers.** ANY page's **cover** (one wire node field, `coverAssetId` on `object.update` — never a property; the retired image-typed `cover` property is superseded) renders as a collapsible card beside the title, never a property row (the Properties panel suppresses it). The element is the cover CARD: it sits in the header row's RIGHT column — collapsible via the chevron, ALWAYS rendered even when empty (collapsed to the strip by default; a cover that IS set expands the card automatically — the new image is the feedback; expanding reveals the dashed "Add cover" card, the image, or a placeholder naming a byte-less asset) — and accepts a dropped image file (or drop an image file on it). A cover IS an ordinary **asset**-classed node (the dedicated `cover` class was dropped: it duplicated the property's meaning) — the field is the only authority, so a cover set by any client shows in the header card at once. A cover whose asset has no image bytes renders a dashed placeholder naming the asset, never a silent void. No cover value → the collapsed strip still shows; whiteboard pages and embedded feeds skip the element entirely. The referenced asset wears a **Cover** badge in card views (derived from the field — a cover is a plain asset; there is no separate cover class) and cover assets list under the asset class's classed nodes. Imagery is LAZY: card lists render placeholders instantly and fetch bytes only as the viewport nears; clicking a cover — in the header card or any card view — opens the floating **lightbox** (download, fullscreen, Esc). In card views the cover slot renders even when EMPTY — the collection-view ruling is [views.md](views.md#covers-in-card-views).
- **Banners.** ANY page may also carry a full-width **banner** above the header, spanning the content width inside the page card. It is one wire node field (`bannerAssetId`, written by `object.update` — never a property), collapsed to a slim strip by default (the per-page device-local pref). Expanding shows the fixed-height cover-fit image — or a dashed **Add banner** affordance when none is set, which opens the upload modal (images only — the accept list and the size caps validate client-side, and a pasted file fills the drop zone). The page context menu carries no banner entry — the banner row's own affordance is the UI (one surface per action). Hover reveals Collapse / Change / Remove; Remove clears the field and leaves the asset. A banner landing while the strip is collapsed expands it — the new image is the feedback. Banner and cover coexist (banner above, cover card in the header row); whiteboard pages and embedded feeds skip the banner too.
- **The context column** (the main layout's third column, beside the properties panel — the two side columns wear the same card element as the main content container, nested inside it) carries the open page's context: the **local graph** card (the page's neighborhood, depth 1–3 — [graph.md](graph.md)) — a collapsed-by-default collapsible section whose graph mounts, and loads, only on the first expand, so a closed card costs nothing — **Table of content** — the page's heading blocks only (a block becomes a heading via **Convert to heading** in its context menu; **Convert to plain text** converts back), nested one level under heading ancestry, hidden while the page has no headings; clicking an entry jumps the main view to the block — the page's own **Activity** (Created, plus Edited when the page was touched after creation — never the workspace's feed; the feed is a bounded summary by design, [views.md](views.md#long-lists--one-pagination-convention)) — **Version history** — the page's own slice of the operation log: every op naming the node (edits, trash/restore, moves, property writes), newest first, collapsed by default and fetched on the first expand like the local graph; a content edit expands to a read-only snapshot of that version, and **Restore this version** rewrites the content with an ordinary update — the log keeps the current content's own op, so restoring never destroys anything — and **Comments** — threaded notes classed `comment` (a reply nests under its comment), always rendered even when empty (an empty thread starts expanded, its icon-only quick-add one click away), with a per-row Reply/Delete pair. (The footer with the word count + Created/Updated stamps retired 2026-10-28 — owner call.) Each column keeps its own collapse toggle in the page's top bar, remembered on this device; every section except Comments hides when it has nothing to show. The **Activity** section renders on the main page surface only — embedded feed entries and other secondary surfaces skip it, since they already sit on aggregation surfaces; a block's edit time surfaces on its page, not here. (The page's incoming linked references are NOT here — they live once, in the Backlinks section below the content; the old right-panel References list duplicated that same data and is gone.)
- **The right panel** (sidebar toggle, or shift+click anything) is the workspace-cards rail: any node you shift+click opens there as an independent card — the same NodeView as the main card in compact chrome — so you can keep several nodes beside the main view. The gesture rides every surface that names a node: a block bullet (on the page body, in the focused block view, inside a rail card or floating window), the page header title, a favorites/recents sidebar row, a property value cell's carrier bullet — and the command palette's node rows answer **Shift+Enter** the same way ([search.md](search.md)). The rail is a **fixed-height column** — it fills the shell height no matter how few cards it holds and scrolls internally when the stack outgrows it — with a slim **top bar** as its only standing chrome: **Add** on the left opens the page picker to card a node directly (the empty rail's door), **Clear all** on the right empties the stack and closes the panel (visible once any card exists). A node renders as a **single card instance**: re-peeking a carded node moves its card to the top — the stack order IS the peek recency, persisted device-locally (`notees.sidebarCards`, never an op); there is no reorder gesture. Each card is a solid surfaced card (the main content card's surface) whose hairline-separated header carries, left to right: the **collapse chevron**, a **non-clickable right-anchored breadcrumb trail** (on overflow the upper parent levels hide behind a plain "…" — the current levels always show), and on the right the **card-actions menu** (the three-dot: Open in main view — which navigates and removes the card —, Close, Close others, Close all, Collapse/Expand, Collapse others, Collapse all, Expand all) plus the **close X**. Collapsing is card management, never node state: a collapsed card hides its body and keeps the header bar. Dragging a block onto a card's header still drops the block into that card as its last child — the header remains a block drop target. The node's page-context widgets (Contents, the local graph, Activity, Comments) live in the main layout's context column, not here.
- **Child pages** — the page's main children (the Pages zone) render as their own read-only tree section, always rendered on the main surface — an empty section says "No child pages." — with the create riding the **section header's trailing action** (the + at the header's far right creates a child page;). The same header-action slot carries Comments' add and the class view's add-member. Embedded feed entries keep the old ruling: no create affordance, and a childless entry hides the section.
- **Breadcrumbs edit.** Crumb labels are **plain text** (the chrome-label derivation): a title's markdown links reduce to their label — never raw `[label](href)` — and an inline class chip shows the class's current name. Hover a crumb for its chevron (or right-click it): the crumb expands to make room for it, so the resting trail keeps even spacing; the menu: Open, **Reassign parent…** (a node picker), **Remove parent** (detach to the workspace root) — and a parentless page gets a "+ Add parent" pill. A parentless page hides itself from the trail — there is no chain; class nodes show no breadcrumbs at all (classes are always roots — a parent is unrepresentable). All of it is ordinary tree surgery (one move per gesture).

**Deliberately not included:** per-class page layouts and wide/profile/encyclopedia geometry (a layout property would ride a class-bound select property — i.e. semantic state, so the decision stays open), index-card length constraints (title-is-content rejects them).

### Narrow screens

Below the tablet breakpoint the chrome adapts without becoming a different app: the sidebar drawer gains a real surface above the page beneath it, sidebar rows grow to the button-height token and the shell's icon buttons reach the 48px M3 touch floor (the favorite star stays visible — there is no hover to reveal it), the topbar wordmark yields to the breadcrumbs, and page/card padding tightens. At phone widths an open right rail becomes a full-width bottom sheet (safe-area aware) instead of disappearing. A **floating action button** (the quick-add) hovers over the content at these widths — tapping it opens the Quick Add modal (same flow as Ctrl/Cmd+Shift+N, [calendar.md](calendar.md#quick-capture)) — and tapping **outside the drawer dismisses it** (the press must land off the drawer and off the topbar, where the hamburger lives; desktop widths never dismiss).

## Presentation mode — the note is the deck

There is no slide editor and no slide objects: a presentation is a pure read of one page's subtree, split into slides by the same tree that holds the content (structure is the slide boundary — the content grammar's `heading` token marks document structure for the Table of content, not slide boundaries; slides follow the tree).

Any page decks itself: the "…" node menu (top-right of the content card) → **Present**, the page header's right-click menu → **Present**, or **Ctrl/Cmd+Alt+Enter** with the page open. (Capacities uses Ctrl+Alt+P; that chord stays reserved for add-property here.)

- **Slide 1 is the page itself** (title, icon, color; the page's own text content, centered, with its icon and effective color); each child in its **Pages** zone opens a section slide (its text is the slide title, its children the body; nested blocks included); inline body blocks chunk into intro slides by a density rule — a run of inline-body children becomes one or more intro slides, closed greedily by a character budget and a block cap: short slides read large, dense slides compact, and a slide that still overflows scrolls inside itself instead of spilling off the stage; a trailing image block pulls aside (text left, image right, or centered when alone — when the last body block of a slide is an image, an `asset` reference and nothing else, the slide splits; an image alone centers at full size); embedded pages expand their children into the stream after the referencing slide — the live-subtree embed rule is untouched; expansion adds slides, replaces nothing. **Tables render as tables** — a table-classed body block rides the same BlockRow grid branch the embeds use — rows and cells render as a grid on the slide, not a flattened list.
- **Navigate** with ← → ↑ ↓, Space, PageUp/PageDown, the screen edges, or the floating toolbar (previous / counter / next / exit — it fades while you read and returns on any movement or keypress). **Esc** exits.
- **Read-only but live.** The deck is a live, read-only read of the note — there are no slide objects; it re-renders through the ordinary notify path as the note changes, and nothing in a deck writes or edits the note. Following a link inside a deck exits and opens the target in the app.
- **Session view-state only.** Reopening a deck within the session resumes at the slide you left — the index is session memory only, never persisted, never synced; it dies with the page session.

The overlay host is a UI-kit primitive (`PresentationOverlay`), sized for a second consumer — whiteboard fullscreen — later. The deck builder, slide renderer, overlay, entry points, and session resume are in the web app, with full imagery support: asset tokens render as live images inside slide bodies (click → the lightbox), a trailing image block drives the split/full-bleed layouts, and the presented page's — or a section's — **cover** renders as imagery (the title slide's hero; the right column of a cover-split slide). Desktop-class surfaces only; a phone deck is deliberately out of scope (the mobile client is capture-first). Speaker notes and deck export stay parked — page Markdown export already covers "get the content out" ([exporting.md](exporting.md)).

## Promotion and demotion

A bullet's prominence is soft state — one op flips it, and identity is preserved completely.

- **Block → page:** a bullet that outgrew its parent becomes a page in place. Same node, same id, every link intact; recents, search ranking, and the link dropdown pick it up automatically because they rank pages first — no re-filing, no copy.
- **Page → block:** demote a page back into the flow of another note; same in-place flip.
- **Declare a class:** create the node with the class identity (`notees object create --isClass` — a `class.create` op under the hood). The node becomes a root, leaves the content tree, and gains the Class View and configuration. Declaration-first: create classes, configure them, use them later or never.

The canonical story: a `meeting`-classed bullet in a daily note sits quietly for months. When it starts to matter, promote it — clear its embedding flag (`--no-isEmbedded` — the standalone claim), optionally nest it under the company page. Same node, same id, all links intact.

The flip is real from the CLI and object API (`notees object update <id> --no-isEmbedded` — see [cli.md](../cli.md#a-real-session)) and from the editor: the block's context menu carries it as **Convert to page › Keep under "…"** (promote) and **Move to content** (demote, on a parented page) — one undoable `object.update` each ([undo.md](undo.md)). Because promotion flattens a block's content to plain text (title-is-content), the conversion asks first when the block carries rich tokens — the confirmation names what will flatten (mentions, typed links, attachments, …); whiteboards and queries survive untouched, and plain text converts without asking. Recents/dropdown re-ranking and the class-declaration flow are designed.

## Converting a block to a page

A block's context menu (right-click the bullet area or the row's text) → **Convert to page ›**, one entry for every "make this block a page" outcome, each a self-describing choice: **Keep under "\<parent\>"** flips the block into the parent's Pages zone (it stays in the family — and its rich content flattens to plain text, so the menu asks first, naming what will flatten); **Extract without children** turns the block into a root page of its own — the same node, not a new one — and leaves a link block holding just a mention of it in the block's exact slot, the children remaining in the original page under that link, their order preserved; **Extract with children** does the same but the children move with the block. Hover either extract row for the full explanation — the rows name what the extracted node keeps. Root is named in the tooltips on purpose: the node leaves its parent entirely. A parented page instead offers **Move to content** (back to the inline body) — date-chain nodes never: their journal role is platform-fixed, and an `isEmbedded` write on one fails loud at the store; pages and date-chain nodes never offer the submenu.

## Copying a node

Any node's context menu → **Copy ›**: **Markdown** copies the node's own content as markdown; **Markdown with children** adds its child blocks as nested bullets (frontmatter-free, ready to paste anywhere); **Node id** copies the raw UUID (for the CLI and API); **Link** copies the app's node link.

## Dividing a page

Type `/hr` in a block → **Divider** inserts a horizontal rule: a new block whose content is exactly `---`, rendered as a line at display time (nothing new on the wire — the block is an ordinary citizen; click it to edit the raw dashes, and typing anything else turns it back into an ordinary block; Backspace from the next block deletes it). Children nested under a rule never render — a rule terminates a section. In the editor the same gesture lives in the gesture table ([outliner.md](outliner.md)).

## Merging pages

Merge is the disciplined way to retire a duplicate: the **source** page folds into the **target** page and trashes itself. It is one deliberate gesture, never a silent side effect.

With a page open, the command palette (**Ctrl/Cmd+K**) offers **Merge current page into…**: pick a target page and the current page absorbs into it — the dialog names both pages (the source is the open page — not re-pickable — and asks only for the target, then a danger confirmation names both titles before anything writes), and the merge is one undo step (Ctrl/Cmd+Z brings the source page back).

- **Everything remaps.** The source's blocks and child pages move to the bottom of the target (order preserved); its class memberships and tags transfer; its authored properties copy into empty target slots only — **the target never loses a value it already had** — and multi-value properties union. Everything that *pointed at* the source retargets to the target: mentions in other pages (including inside quotes and headings), node-typed property references, aliases, collection memberships. Cover, banner, and description fill only when the target's field is empty. The source's own title does not transfer — title-is-content means the target keeps its title. The merged page moves to the trash.
- **Guarded combinations** — a class, a non-empty collection, a target inside the source's own subtree — are refused with an explanation, not a half-merge.
- **One undo step.** The whole merge is a single journal entry: Ctrl/Cmd+Z restores the source page from the trash, moves its children back, and reverts every remap. (Undoing a merge after further edits to the target follows the journal's usual honesty — it rewinds what the merge wrote, not what came after.)
- **Every surface speaks it.** The same gesture is on the server at `POST /api/objects/:id/merge` (with `?dryRun=true` returning the plan's counts) and in the CLI as `notees object merge` — preview-first with `--dry-run` (see [api.md](../api.md) and [cli.md](../cli.md)).
