# The graph view

The workspace as a map: the sidebar's **Graph** row (or setting your landing view to "Graph View") opens the whole workspace as one interactive map — every page and class is a node, every link is an edge, laid out by a force-directed simulation running off the main thread and drawn by the PixiJS renderer (WebGL). The design law that keeps it readable: **blocks never render** — a link authored on a block rolls up to the page holding it, so the map shows the workspace's pages-and-classes skeleton. The map renders edge-to-edge in the content card — the card frame is the only chrome. The same map is also a **collection view mode** (below) — any collection that carries links can wear it.

## Moving around

Drag empty space to pan, the wheel zooms (cursor-anchored) — over the canvas or the minimap, which also takes scroll-to-zoom. The bottom-left **control dock** holds recenter, pause/play (the simulation, session-only), zoom in/out (canvas-centered), and **Focus** (shown while anything is selected) — it fits the selection's bounding box (a single selected node centers at a comfortable zoom). Drag a node to rearrange it (physics keeps settling around your pins); **click** a node to add it to the selection, **double-click** opens it (and clears the selection), clicking empty space clears. Hovering a node highlights the node, its links, and its linked pages in the app's **accent color**, while everything else stays visible but dimmed, keeping its own color; the hovered node's label always shows — nudged just a little below the node — as the identifier (no tooltip box); hovering an **edge** names its kind, weight, and the pages behind it. With the graph surface focused (click the canvas), the keyboard works too: **+/-** zoom, the **arrow keys** pan (**Shift** = 4×), **F** focuses the selection, **R** recenters.

## Interaction is the outliner's

Drag to pin, click to select, double-click to open, find jumps by name. Positions persist per workspace, so the map greets you where you left it. Reduced motion starts the layout paused.

## What the edges mean — families are honest

Every edge names its kind, and the **Visibility** popover's family chips toggle each link type independently: **Mentions** (one page links another), **Properties** (a property value points at a node), **Parents** (page containment), **Classes** (membership), and **Semantic** — the distinctive one: two pages are semantically linked when something mentions both in the same block. Semantic links are content-proximity: the weight is the shared-block count (how many blocks co-mention the pair), a hover card names the blocks behind the link, and a context that mentions more than ten pages contributes no semantic links (an index page would otherwise spray a clique). **Temporal** is the day's cousin of semantic: pages mentioned anywhere inside the same day page link together, hover names the day. A relation that runs **both ways** draws as one line with an arrowhead at each end. Counts always read the full filtered set; the orphan toggle hides the unlinked.

**Semantic detail** — the Visibility popover's two sliders bound the semantic web: top-N strongest links per node, and the minimum shared-block count a link needs to appear. Raising them thins the noise; lowering them surfaces weak associations. The cuts are display-only — nothing is deleted.

## The right rail

The top bar's **Colors** chip and (while anything is selected) the **Selected · N** chip open a rail at the graph's right edge — a card with two collapsible sections, both resting collapsed, open/close remembered on this device. The rail is a true layout sibling: the map shrinks to make room and the minimap hugs the remaining canvas. **Selection** carries a permanent node search — type to narrow the workspace, click a result (or press Enter for the first) to **add it to the selection** (search-to-select never edits the graph; there is deliberately no create row) — above the reorderable selection list (drag to reorder, remove one, or **Clear**). Clicking **Selected · N** opens the rail scrolled to that section. **Colors** carries the painting controls (below).

## Colors — query groups only

The rail's Colors section paints nodes via **query groups only**: the full visual query builder (the same condition blocks the table/list filters use — class, type, content, property, links, parent, created/edited…, [queries.md](queries.md)) defining each group's nodes — `class:book`, `prop:status:done`, a property name — a name (optional) and a color swatch per group. The group list is drag-sortable and **the order is the priority** — a node matching several groups paints with the first listed; a node with no match keeps its own color. The panel validates the query as you type. The retired per-class color list migrated one-time into groups (each class became a class-matching group). The **Paint groups** switch turns the painting off without losing the groups. Settings persist per device.

## Layouts, physics, and the chrome

- **Layouts.** The bottom edge owns the canvas: the bottom-left control dock, the **mode bar** bottom-center switches the layout — **Force** (the simulation), **Circle**, or **Tree** (concentric rings by parent depth — children always one ring out; radial rings by parent depth) — and the corner **minimap** bottom-right. Fixed layouts are deterministic; drag still rearranges. The bottom **mode bar** offers Force, Circle, and Tree.
- **Physics** — four presets (Sparse / Balanced / Compact / Clustered) and node sizing by metric (Uniform / Connections / Mass / Content). The simulation is energy-gated: it settles to a true equilibrium, then rests — dragging a node reheats only its neighborhood, so the rest of the map stays exactly where it was. Your layout positions are remembered per workspace, so the map greets you where you left it. The graph opens framed on first paint and cools to equilibrium quickly — a cached workspace opens nearly still and finishes settling within a second or two. The **settings** popover (the cog) is the drawing engine + physics + sizing: the **Physics preset** (a named dropdown), **Simulation** (run/pause), **Link-count attraction**, **Central gravity**, **Mass accumulation**, **Clustering** (communities hold together and separate — the **Cluster separation** slider scales the gap), **Node sizing**, the **Node radius** slider, and **Link direction**.
- **Time lapse** — the mode bar's toggle opens a slim timeline strip above it that replays the graph's history: nodes appear at their creation time, edges when both endpoints (and their own stamp) exist. **Play** animates the cutoff from the oldest node to the newest over ~20 seconds; the scrubber drags it by hand. The **Edges** switch turns edge fade-in off (edges stay static while nodes still animate). Closing the strip (or toggling it off) returns the full map. Session-local, like pause — nothing is deleted, this is a display cut only.
- **The Visibility popover** decides what is drawn: the link-family chips, **Class nodes**, **Orphans**, the two **Semantic detail** sliders (riding next to the Semantic/Temporal families they bound), and the journal **Visibility** levels (**Day / Month / Year pages**, **System pages**). The eye lights while anything is hidden. **What stays out by default**: the journal chain (year/month/day pages, each level toggles in the Visibility popover) and any node family you toggle off; the counts in the top bar always name the full filtered set, never just what's drawn.
- **The chrome** — two transparent bars and one edge rail frame the graph: the top bar holds the quiet canvas controls (the **Visibility** eye, the settings cog, the counts, and the Colors / Selected chips). Neither bar carries a background; the canvas runs edge to edge beneath them. The corner **minimap** shows the whole map with your viewport — click or drag it to move, scroll to zoom.

## The local graph card

The page's context column carries the **local graph** card for the open page — its neighborhood (depth 1–3) with the same interactions at card scale ([pages.md](pages.md#page-chrome--what-sticks-and-where)). An empty local neighborhood names the depth to widen.

## The graph as a collection view mode

Every collection surface — a hub, a class's members, the Created section, a page's child blocks — can wear the map through its view switcher: the scoped map's universe is **the collection's items rolled up to the graph node set** (the blocks-never-render law at scope time — a block item maps to the page holding it) plus the **edges among them**. An edge whose rolled-up endpoint lands **outside the collection drops** — the scoped map draws the collection's own pages-and-classes skeleton, never dimmed external nodes: a collection graph answers "how do THESE connect", not "what else exists". The renderer, layouts, families, colors, and time-lapse are the full map's unchanged. The mode is **availability-gated**: a collection offers the map only when at least one item carries a node link or mention ([views.md](views.md#view-availability-gating)) — a link-less collection has no map to draw and no dead switch appears; a saved graph mode the collection can no longer feed falls back to the surface default. The choice persists device-locally like any view mode; the sidebar's Graph row stays the whole workspace, always.

## Honest states

The graph renderer needs a GPU-backed canvas (WebGL 2) — without it the view says so honestly instead of rendering half a map. An empty workspace says **Nothing to graph yet**; when your filters hide every node the view offers **Reset filters** (back to the shipped defaults). No canvas mounts for an empty map. A scoped collection whose items survive neither the scope nor the filters says **Nothing to map in this collection** — the reset affordance stays the full surface's alone (a scoped map has no workspace filters to reset).
