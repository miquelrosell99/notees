# Classes

A class is a node: addressable, linkable, annotatable, in the same table as the things it classifies — and *for* configuration: property bindings, inheritance, templates. This page covers the class view, creating classes, the three ways a node touches a class (assign / inline chip / mention), and the workspace feature toggles; why classes-as-nodes is the law is [philosophy.md](../philosophy.md#classes-are-nodes); class chips and the `+` class picker are [links.md](links.md); the classed-nodes table and cards ride the collection rulings in [views.md](views.md).

## The class view

A node marked as a class (always a root) gets the **page view itself** — same chrome, same editable bullet-tree body (classes are containers and can hold child blocks) — plus class-relevant sections. The class page renders the **panelled layout** (owner 2026-10-12): the first column hosts the **Properties** panel + the **property definitions** list (one row per binding — drag to reorder; the row click opens the property's base-definition modal where the schema-level default + render contracts live; the class-level inline editor is gone, owner ruling 2026-10-20 — the default is one global per-property value, the Logseq shape, and `required` retired outright) + the **templates** cards (bound instantiation templates — see [templates.md](templates.md)), while the content column keeps the **classed nodes** table (the members — one column per property definition, table by default, outline/cards switchable; cards renders the **board** when a bound select property can group — one column per option, drag a card between columns to set its value; the class page's centerpiece, the Capacities/Tana lesson: instances are the page; the section header's **Add member** action and the empty state create a node classed with the class — visible even when the class has no members yet). The app top bar's **layout button** flips the current node between the sidebar layout and the in-flow **sections** layout (Properties + property definitions + templates stacked in the content flow, the extends pills pinned to the card's top-left corner) — session-only, never stored; the icon names the active mode. The **extends** pills (the class's extensions, added with "＋ Add class extension" from a class-only selector; × removes an extension; cycles fail loud) ride the nodeview top bar in the panelled layout, the card's top-left corner in the sections layout. The class page carries the **context column** too (owner 2026-10-12 — graph/TOC/Activity/Comments are node-relevant for every node kind, class pages included; the column is [pages.md](pages.md#page-chrome--what-sticks-and-where)'s). The class's color and curated icon live in the header (one dot opens the picker; the swatch strip is gone). Below the body, the standard system sections plus **Extended by** (the extenders as a tree of direct extends edges — a subclass nests under its own direct parent, never as a top-level row under an ancestor; a backlink-class read). There is no separate description shelf: title-is-content means the class's title IS its description.

Class nodes are always roots by construction — `is_class` implies no parent, enforced by a schema CHECK and a fail-loud move-guard; the one tree rule left is that a class can never be a child. Classes may themselves have non-class children. Inheritance is data: `extends` is an m2m node-typed property between class nodes — multiple inheritance from the start, diamonds natural, cycles rejected fail-loud — and effective membership is own classes ∪ ancestors, with a deterministic binding-resolution order (own binding → shortest extends-path → earliest-authored) ([philosophy.md](../philosophy.md#classes-are-nodes)).

## Creating classes

The **Classes** hub's **New class** button (or the command palette's **New class…**) opens the creation dialog. The **Blank class** tab is the ordinary create (name, icon, color). The **Gallery** tab is a Capacities-style card grid of the seeded system classes this workspace does not have **enabled** — icon, name, and a one-line description, grouped in sections (People, Sources, Events & tasks, Knowledge, Media) — with a **Create your own** card switching back to the blank form (the typed filter carries over as the name). Picking a card **enables** the class: it is authored at its designed identity, its place in the hierarchy, and its property family in one idempotent step (the family bases ride their feature toggle — picking Task while Tasks is off switches the family on), and a class that exists but is **disabled** shows its card with a "Currently disabled" note — picking it brings it back. Locked classes (the date chain, table, asset, query, code, template, comment) never appear: they are platform structure and cannot be disabled. Declaration-first is the standing rule: create classes, configure them, use them later or never ([pages.md](pages.md#promotion-and-demotion)).

## Assigning a class: pill, inline chip, or mention?

Three gestures touch a class from a node, and they answer different jobs — reaching for the wrong one either classifies nothing or shows the class's name twice:

- **Assign** (the `+` on the classes row, or a plain pick in the editor's `+` popup) — classification as *metadata*. The pill rides the node's chrome and the prose says nothing. Right when the type word doesn't belong in the sentence: a meeting note whose body never says "meeting" — the pill carries `Meeting`, the body just takes notes.
- **`+Class` inline in the text** (a Ctrl/Cmd+Enter pick in the `+` popup assigns and inserts it in one gesture) — classification with the class's name as the marker *inside* the sentence: "report for essay XXX" with `report` as a chip classifies the block and reads as prose. The chip replaces the pill — never two visible references — and the wire asserts the membership. Right when the sentence leads with or contains the type word.
- **`@Class`** — not classification at all: a node link to the class *as an entity*, with backlinks and graph edges. Right when the prose points at the class itself ("had a @reunión with GMI").

The rule of thumb: **if the type word appears in the sentence, let the word be the marker (`+`); if it's only metadata, let the pill be the marker (assign); if you're pointing at the class as a thing, use `@`.** And never write the class's name as raw text: plain text classifies nothing and goes stale on rename, while the pill and the chip both re-resolve the class's live name.

## Disabling and deleting classes

There is one delete gesture, and the system picks the most reversible interpretation — **membership always rides**: removing a class never strips it from the nodes that carry it; enabling or restoring the class brings back every assignment intact (stripping a class from a node stays the explicit per-node remove on its pill).

- A **family base** deleted (Task, Event, Meeting, Source, Person) turns its feature toggle off — the whole family hides, instances keep their data.
- Any other **system class** (a quote, a callout, a source-family member, …) deleted is **archived**, not trashed: it disappears from pickers, search, and hubs, and the gallery's card shows it as disabled — pick it to bring it back.
- A **user class** deleted goes to the trash like any page — restore brings the class back with every assignment intact.
- **Locked classes** cannot be deleted or archived at all.

The same archival state exists for **any node**: the node context menu (page header or block) offers **Archive** — no confirmation, it is reversible — and the **Archived** hub (the account popup, beside Trash) lists archived nodes with **Unarchive** and **Delete** (to the trash). Archived is a state, not deletion: every default read filters archived and trashed content, and unarchive rides the archive gesture — restore is only for the trash.

From the CLI and API, declaring a class is `notees object create --isClass` (a `class.create` op under the hood) — see [cli.md](../cli.md) and [api.md](../api.md).

## Workspace Settings → Features

The core class families as per-workspace toggles: Tasks, Events, Meetings, Sources, Persons — plus the **Journal** toggle below them. A family off hides its classes from pickers, search, and hubs (family changes cascade — Events off hides Meetings and Birthdays too) while existing objects keep their data and stay in the graph. Turning a family **off** with existing instances asks first — the confirmation states that the objects keep their data and the family's surfaces hide (Cancel changes nothing); an empty family (or any enable) switches immediately. The **Journal** toggle is surfaces-only: off hides the journal view in the sidebar and Today-page management (no day page is auto-created); the date classes themselves stay always-on structural seeds.

Below the toggles, the **Sources** section carries the family's settings (one `workspace.feature.set` write per change, the merged settings record riding the row's whole-row LWW):

- **Citekey pattern** — compiled against the citekey pattern language: tokens `[auth]`/`[auth:lower]` (the first author's family, `:lower` ASCII-folds), `[year]`, `[title]`/`[title:lower]`/`[title:lower:N]` (first N words), plus literal text; the default is `[auth:lower][year][title:lower:3]`. The input previews a sample entry live, an invalid pattern shows its error and is never written, and the committed pattern only affects future generations — existing citekeys are never recomputed.
- **Metadata resolver** — look up DOIs and ISBNs against public metadata providers when a source lacks metadata. A lookup reveals the queried identifier to the provider, never workspace content.
- **Auto-citekey** — fill an empty citekey from the pattern when an import integration creates a source.
- **Source types** — all 39 source type-classes as checked rows: unchecked is archived, the same archive flag the gallery and the pickers respect — enabling a row here and picking its card in the gallery are two doors to one switch.
- **Add source…** — the add-source dialog (the command palette's **Add source…** row is the primary door; pasting a DOI/ISBN/arXiv/PDF link into any node picker's create row offers **Create source from link** as a third). One input accepts a DOI, ISBN, arXiv id or URL, a PDF link, or a PDF file: the server resolves the identifier (Crossref / Open Library / arXiv, or the DOI printed in a PDF's bytes), and the create form opens prefilled — type, title, authors and editors as plain "Family, Given" text (one entry per `;`- or newline-separated name; no person nodes are created), the type's venue fields, year, DOI, ISBN, URL, publisher. A resolved archived type is re-enabled automatically (the un-archive and the create are one undo step). An empty citekey auto-fills from the pattern when auto-citekey is on (a deterministic `a`/`b`/`c` suffix disambiguates collisions, compared case-insensitively). A DOI or ISBN already in the library shows an "Already in your library" warning with a link — creating again stays allowed. Failures are honest and create nothing: a PDF with no DOI says so, a disabled resolver points at this settings section, and a plain URL with the resolver off becomes a plain weblink page instead.
