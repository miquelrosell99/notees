# Exporting

Export is a **projection of the graph into files — one-way by design** (the operation log is the truth) — engineered to be as round-trippable as possible. We state this in the header of the document rather than let you discover it: the log is the truth; export is how the truth leaves the building ([philosophy.md](../philosophy.md)). The table views' CSV/xlsx cuts and the workspace zip are here; the CLI export commands are [cli.md](../cli.md)'s companions and the headless endpoints are [api.md](../api.md)'s.

## The dialog is honest about scope

The node menu (context menu / page header / "…" button) → **Export**. Every format delivers real bytes: **Markdown**, **HTML** (standalone, print-friendly), **Word (.docx)**, **LaTeX** (with a bibliography built from source-classed nodes), **PDF** — three layouts (Notes = the app look, Essay = single-column typeset, Academic = two-column numbered headings) on A4 or Letter, rendered in the browser with a bundled open-license font (nothing leaves the machine; the heavy renderer loads only when you first ask for it) — and **JSON archive**: the subtree as one structured `notees-json-archive` document (versioned envelope; the highest-fidelity projection, the disaster-recovery artifact). Source-classed nodes also export as **BibTeX (.bib)** and **CSL JSON** — one document for the whole selection, one entry per node, the same dual-track authorship read as the CLI (`authors` first, linked author agents when empty); body blocks never become entries. Options collapse open with per-format checkboxes (include child pages, hide empty properties, include asset files for Markdown, …). Markdown and PDF get a live preview; the others state plainly that preview is a Markdown/PDF affair. Export downloads one file named after the node — `<title>-<YYYYMMDDHHmm>.<ext>`, so repeated exports never overwrite each other — or a `.zip` when assets are included or several nodes are selected at once.

## The node is the export root

A page (or a block, or several selected nodes) exports as Markdown with YAML frontmatter: the title derived from its content, its classes and properties (per-value qualifiers preserved). Its block tree becomes nested bullets in child order; child pages become their own files. Nothing is lost silently: cycles and depth cuts render as visible `[[uuid]]` references, rich text is Markdown-escaped, whiteboard layouts ride along as sidecar JSON inside zips.

In the PDF the node's title is the only place its own text appears (the body never repeats it); inline blocks render nested body-only with the outliner's bullet dots (Notes layout); child pages form the recursive list at the end — the page view's shape. Mention chips carry the node's icon (drawn from the same icon sheet the app uses), and the **Show classes** option (Options section, all formats) renders every row's class pills on the far right — colored, recursive for child blocks, exactly like the list view. Page size (A4/Letter) rides the same Options section as a dropdown. Text-property carrier blocks never appear in the exported body — they render in the property row, as in the app. Properties render values honestly: booleans as checkboxes, dates in your date-format setting, never a raw node id.

## Zips keep the graph contained

Multi-file exports rewrite cross-page references to relative links (`[title](<file>.md)`) and name files `<title-slug>-<id8>.md` (human-readable `<title>-<id8>` files + `notees-manifest.json` for Markdown) — human-readable, still identity-anchored (the id8 is a hash of the node id). The JSON archive — and the bibliography formats (BibTeX/CSL JSON) — stay one document for the whole selection. An optional assets folder carries the bytes behind `asset` references as `assets/<name>-<hash8>.<ext>`. A manifest maps every file back to its node id.

## Tables export what you see

A table view (a class's classed nodes, query results, the tasks table) — the table toolbar's **…** menu's **Export CSV** downloads the *current view*: the visible columns × the full sorted result set (hidden columns stay out; the row window is display-only, never an export cut — [views.md](views.md#long-lists--one-pagination-convention)). Cells render exactly as on screen, RFC-4180 quoting keeps commas/quotes/newlines intact, and a UTF-8 BOM lets Excel open the file with the right encoding. **Export Excel** writes the same cut as an `.xlsx` — with a leading **uuid** column, then the visible column labels, and typed cells for number columns — so the sheet round-trips back through **Import table…**, which appears on editable tables in the same **…** menu. The import accepts `.csv` or `.xlsx`: the first row names the columns, a `uuid` column (any capitalization) marks rows that **update** the node with that id (a non-empty title cell renames it, an empty property cell clears it), and rows without one **create** new nodes — a `name`/`title` column is the new node's title, a `class` column assigns classes by name, and every other header matches a property schema by name (select columns match option labels, node columns resolve by name, dates are ISO `YYYY-MM-DD`). A preview step shows the mapping and how many rows will create vs update; cells that can't be coerced are collected into a per-cell report at the end — nothing is guessed.

When rows are checked, two scoped actions appear next to the count: **Export selected CSV** (the same columns over just the checked rows) and **Export selected…**, opening the export modal scoped to exactly those nodes — any format, over just the selection. Cards collections — the flat grid and the grouped board alike — offer the same machinery: a card checkbox accumulates a session selection, and **Export selected…** opens that modal over the checked cards. Every view exports its selection identically.

## The workspace exports whole

The workspace switcher's Export entry opens a small dialog: optional "Include asset files", then one `.zip` download — one Markdown file per top-level and child page (properties in YAML frontmatter, cross-page links rewritten to relative file links, whiteboard layouts as sidecar JSON), an `assets/` folder when included, and the manifest mapping every file back to its node id. The system pages (the inbox; scratchpad pages from before the feature was retired) and the journal date chain (year/month/day nodes) are excluded — scaffolding, not exportable content; exports are for your content, not the calendar's framework. The same zip is available headless: `GET /api/workspaces/:id/export.zip?includeAssets=0|1`.

## From the CLI

`notees export markdown --ids <id>… | --linked-to <id> | --class <id|title> [--depth N|fixpoint] [--output-dir <dir> | --stdout]` builds the same Markdown bundle (bullet order follows child position; `--class` seeds the bundle with the class's current members — the natural "export this class" selector), and `notees shell`'s `exportMd(ids)` returns it as text. Markdown escaping, full-depth closure (no silent truncation), and whiteboard sidecars are the engine defaults. `notees export json --ids <id>… | --linked-to <id> | --class <id|title> [--depth N|fixpoint] [--output <file>]` builds the same JSON archive the web modal delivers (stdout, or a file with `--output`).
