# Links, mentions, and references

How Notees links things: mention pills, class chips, typed-link verb marks on words, live embeds, and the reference sections (backlinks, unlinked mentions) every page carries. The pickers' editor contracts (the `@` / `#` / `+` gestures, the verb popover, selection link authoring) are here too — the block-editing gestures they ride are [outliner.md](outliner.md)'s; the filter chrome these sections ride is [views.md](views.md)'s; search ranking is [search.md](search.md)'s.

## Mentions, chips, and typed links — marks on words

All three are tokens in the same flat content stream ([SCHEMA.md grammar](../../packages/protocol/SCHEMA.md)), and all three obey the same rule: **nothing is inserted; the word you wrote is the annotation.**

- **Mention** — a pill. Stores the target's id plus the captured surface form; rendering resolves the *current* name, so renaming a node updates every mention for free — and **edit mode re-resolves the same way** (the one-off `displayText`, else the target's current full title, else the captured form): a stale capture (import-era data with nested-link UUIDs baked into the text) never surfaces in the editor. An optional `displayText` overrides per-link ("the Republic"). A broken target renders the raw id — never silent retargeting — and the link-edit modal offers the honest fix: **create the page with that exact id**, so the mention heals in place (no retarget write). In the editor the pill is an **atom** — one caret unit with the read-mode underline look: arrows select it when the caret reaches it (selected = primary-colored text on a faint primary tint inside a focus-ring outline), clicking it selects (a second click hands the caret back, double-click opens), Backspace/Delete deletes it whole (selected or adjacent), right-click edits/unlinks/deletes it in every view mode.
- **Class chip** — render-only, by decision. Inserting a chip does not assign the class; it references the class node and renders its current name. Assignment is a separate gesture, and a lint may suggest it ("chip present, node not classed — assign?"). Suggestion, never enforcement. In the editor the chip is an **atom** like a mention pill, but visually its own thing (owner 2026-10-13): the **wavy underline** (not the mention's dashed border), tinted by the class's **effective color** — no pill chrome. Read mode renders it the same way, as a link that opens the class. The label re-resolves at build time — the token stores no text — and editing around it never silently drops it; arrows select it, Backspace/Delete deletes it whole, double-click opens the class. Flattened surfaces read the chip's resolved name too: the browser tab title, table-view name cells (and the CSV export and sort key that ride the same text), breadcrumbs included — a title that IS only a chip excerpts to the resolved class name, never "Untitled".
- **Typed link** — the distinctive one. You write the sentence naturally ("argument X *contradicts* argument Y"); the verb is a **mark on the word**, with an optional target and token metadata such as a locator. Rendering is a subtle colored underline with a hover card, plus a global "show types" overlay (off by default in reading mode). Lifecycle is honest: delete the word and the mark dies with it — the graph stops claiming what the sentence no longer claims. The verb is a property-schema reference *or a bare free string*; when the verb you want doesn't exist yet, **create-and-bind** makes the schema at capture time (the Tana lesson: schema-at-capture or the feature dies in setup). The adorned mention pill survives only as the escape hatch for when there is no natural verb ("see <<Y>>").

**Record, don't resolve.** Capture records candidate target spans as an ordered list — implemented as the `targetNodeId`s of the block's mention tokens, nearest-first by prose distance from the mark, capped at 8 (the flat grammar has no token ids; this interpretation is recorded in SCHEMA.md). No scoring, no filtering. Target resolution stays deferred, designed against real captured data.

Citations are the canonical dogfood: a `cites` verb with the locator auto-filled from the current PDF selection, grouped backlinks by verb, bibliography views — the research environment. (The citation import/export round-trip itself is a CLI feature: `notees import/export bibtex` — see [feature-status.md](../feature-status.md).)

**The web editor:** `@` opens the node picker (mentions) with the caret already in its search field — typed at the start of the text or right after any non-word character (whitespace, punctuation, brackets; a word character before it means the email case and stays silent), the same boundary `#` and `+` answer to — scoped by **Main/Blocks tabs**: Main (the default) searches pages, classes, and other document-chrome nodes through the relevance-ranked index; Blocks narrows the same search to inline child blocks, each row labeled with its containing page. Search is live and honest: keystrokes **coalesce ~150ms** before the query hits the ranked index (one search per pause, not per keystroke — it matters on huge workspaces), hits render the moment the index answers — no retype needed — and a **"Searching…" state** rides the list while a query is in flight, never a lying "No matches found". Result rows crop long names (CSS ellipsis); resting the pointer on a row raises a tooltip with the **full title** — the uncapped one, so past the display-name budget the tooltip keeps the whole title, not an 80-char cut. The no-match row **creates the page** (title = the query; a bare 4-digit **year outside the date window** — 1711, 1066 — labels the row **Create year "…"** instead of Create "…", in this picker and the command palette alike; inside the 1900..2200 window the typed-date row owns the year affordance; `class:Name ` typed first narrows candidates to that class and the create lands inside it) and the link inserts **in the same gesture** — the create row waits for the fresh node to land and picks it, no second invocation. Name matching everywhere in the pickers folds diacritics, same as full-text search — `video` finds the class "Vídeo", and the classes tab, the `class:` refine, the template gallery and the bind-property popover all match unaccented queries against accented names (and an unaccented exact hit suppresses the duplicate create row). When the filter is a **source subclass** the create row instead opens the citation dialog — type, title, authors, year, DOI — authoring a properly classed source with linked person nodes; an **agent** filter (person/organization) opens the given/family-name split. Typed dates offer **"Link to daily page: …"** (or "Create …" when the journal page doesn't exist yet — one gesture creates the chain AND inserts the link; the row never dead-ends on a flip to "Link to"). `#` opens tag vocabulary (**Enter assigns the highlighted tag, creating it if missing**), `+` picks existing classes the same way — all three pickers share the **same single-pick contract** (owner 2026-10-15): one row, one gesture, the popup closes — no checkboxes, no picked set, no Apply footer; **Ctrl/Cmd+Enter** picks the highlighted row too (on `@` it keeps the query as a custom label; on `+` — the class picker — it assigns the class AND inserts an inline class link in the same gesture, the direct one-step version of the convert below). To stack several classes, re-open the picker per class. The `+` popup's **already-assigned classes ride the checkmark** (owner 2026-10-15): they hide from the empty-query browse and resurface under a matching query, where a **plain pick REMOVES the class** (the toggle — the checkmark reads as the row's state) — and any inline link to the class dissolves into plain text with the same gesture — removal never leaves a dangling reference, and the wire itself enforces the pair: an `object.update` carrying a class_link **asserts the membership** (any writer converges), while a bare `class.unassign` **refuses** until the links are gone and a **Ctrl/Cmd pick (Enter or click) converts the trigger to an inline class link** — the `+` drops and a `class_link` token (a class marker with the node-link look, NOT a node link: no backlinks, no graph edges) splices at the trigger; the membership stays assigned, and the **classes pills hide any class the content references inline** (the pill row is a derived view — the link IS the marker, never two visible references to the same class; which gesture to reach for — pill, chip, or mention — is [classes.md](classes.md#assigning-a-class-pill-inline-chip-or-mention)'s taxonomy). The divergent state — an inline class link whose class the node no longer carries (undo interleavings, imports, external writers; legal, live data verified converged at the ruling) — draws **dashed**, "referenced, not assigned", and one click **assigns** it back. Filter prefixes refine any of these pickers: **`daily:`** lists (or narrows to) day-precision journal pages, and the booleans **`is_daily:` / `is_page:` / `is_class:`** (true/false) split the pool — the tokens never become part of the search text or a created title. The same filters are one keystroke away as chips: a leading **`/`** opens the pickers' **Filters** list (Daily pages, Pages, Blocks, With class… — narrowed by the slash text, with a class browse behind "With class…"), and an applied chip rides above the results — removable per chip, Backspace on an empty query pops the last one. A **With-class chip** behaves exactly like a `class:` refine, created node included. A selection + Cmd/Ctrl+K (or the toolbar verb button) opens the verb popover: the verb matches the workspace's property schemas live — an exact name hit offers **"Bind to property …"** (the mark carries `verb: { propertySchemaId }`, renders the schema's name, and projects into the edge index by schema id), and a name nobody has used yet offers **"Create property '…' and bind"** — the schema is authored at capture (typed `object`, multi, no class filter) and the mark binds to it in the same gesture. The plain **Link** submit keeps the free-string verb, and right-clicking an existing typed-link word reopens the verb field (same rows) to rebind or edit the locator. Rendering resolves names everywhere, and a node link whose target carries an icon — its own or its first class's effective icon — shows the glyph ahead of the label (defined icons only: an iconless link stays text-only). Still designed: locator autofill from PDF selections and target resolution.

**Node pickers open to your recents.** Every unscoped node picker (the `@` / `#` / `+` popups, the property- and link-target pickers) opens to the device's **Recently used** nodes — most-recently-used first under a quiet caption — instead of an empty list; the first keystroke replaces the recents with ranked search hits. The scoping rules don't move: class-scoped pickers still list their members on the empty query, blocks-mode pickers list only inline blocks, and the classes picker keeps listing classes.

## Node links — open, peek, pin

A mention (the dashed `@`-link) is a door, not just a color: **click** opens the target, **right-click** opens its menu (open, open in the sidebar, edit/retarget the link, remove or delete it), and **resting the pointer on it** raises a bounded preview card — the target's own page view, read-only: the real title row and the top of its block tree (the first level), with its backlink count in the card's footer. The card is read-only on purpose: the editor owns the caret, and a hover surface that grabbed focus would fight the page you're reading — clicking the title or a row opens the node instead of editing it. Click the card's title to open the node, or **Pin** it: the node becomes a small floating editor window — its real view (blocks and all) in a draggable card that sits beside what you're reading, editable exactly like the page (same writes, same undo, same sync), with **Open in main view** and **×** at the title bar's right. Pin an already-pinned node and its window just comes forward. The preview card closes when you move on, press Esc, or click elsewhere; the pinned window stays until you close it.

## External links — markdown, not a token

External links are **markdown spans inside ordinary text** — write or paste `[label](https://…)` anywhere (titles included) and it renders as a plain hyperlink (underline + link color, never chip chrome). Bare `https://…` URLs in the text autolink too — trailing sentence punctuation and a closing paren the sentence owns stay outside the link. **Click gesture:** a plain click does not navigate — the block row owns the click (it edits the block, or opens the node read-only); **Ctrl/Cmd+click** (or Shift+click) opens the link in a new tab. There is no external-link token and no link modal: the `/url` slash command writes `[href](href)` as editable prose at the caret, and the label-carrying path is typing or pasting the markdown yourself — what you see in the editor is exactly what is stored. Every renderer applies the same conservative grammar (SCHEMA.md "Content grammar"): the label holds no `]` or newline, the href no whitespace or parentheses, and only `http(s)`/`mailto:` hrefs linkify — anything else stays literal text. Exports round-trip the markdown (markdown verbatim, HTML/LaTeX as real anchors); the PDF prints it as text for now.

## Aliases

Two kinds, both page metadata, coexisting:

- **Text aliases** — the seeded **Aliases** property (add it from "Add property") gives a page alternative *names*: an alias is searchable like the title and resolves by exact name (`[[…]]` picks, unlinked references). Use it for spellings, abbreviations, alternate wordings of the same page.
- **Node aliases** — a whole *page* linked under a main page: the **Aliases** row at the top of the main page's metadata panel lists every alias as a pill (× clears the alias; "+ Add alias" picks a page and that page becomes an alias of the main — pages only, a non-page target is refused with an error, never written; clicking a pill opens the alias's *own* view). The page header's action-row **Add aliases** is the same pick flow from the header (owner 2026-10-09). Use them for plurals, opposites, translations — any meaning that deserves its own page. A node alias is a first-class page: opening it shows *its* view (its own body, and only its own linked references), topped by an **Alias of \<main\>** chip that jumps to the main page. Everything pointing *at* the alias rolls up to the main page instead: mentions of the alias open the main page's view, the main page's **Linked references** list the alias's inbound links right alongside its own (the alias title also joins the main page's names for unlinked references), and the workspace graph draws the alias's edges as if they were the main page's. The alias's own view stays quiet — it lists only what points at the alias itself — and carries one **Aliased node** row in its metadata, where the alias can be re-pointed or cleared.

## Embeds and asset tokens

Embed tokens render the live subtree, with the **Full/Card/Wide switcher** in the embed chrome writing the token's `view` (Card/Wide are bounded identity cards — never transclusions). The embedding-flag presentation rule (a link marked embedded whose block carries only that link presents the target in its place) is [pages.md](pages.md)'s — the view-resolution side. Embeds are read-only projections, cycle-guarded ([feature-status.md](../feature-status.md)).

Asset tokens render their file with a lightbox — the asset rendering rules themselves (inline preview, filename chip, full-bleed, the missing-asset placeholder) are [the outliner's](outliner.md), since an asset is block content. Asset-typed property rows (sources as containers) are documented in [feature-status.md](../feature-status.md) and [properties.md](properties.md).

## System sections — and the lazy-loading contract

Pages come with predefined sections that are **named system queries** over the query runtime, not bespoke UI: **linked references**, **references** (outgoing), **unlinked references**, **child pages**, **classed nodes**, and **extended-by**. They are fixtures like any op type, and the section registry becomes plugin-extensible later.

The rules, all of them load-bearing for performance:

- **Collapsed by default, and a collapsed section runs no query at all.** Nothing loads until the first expand.
- **Count badges come only from materialized counts** (`node_stats.backlink_count`) — and a section names its count exactly once (owner ruling 2026-10-21, refined 2026-10-23): on the **active tab's badge** when the section is hosted (tabs), on the **section-header count badge** when it has no tabs — plus the **block-level backlink gutter**, which renders on every block row with backlinks. The badge renders unconditionally and is exempt from the contract because reading it is reading a stored number, not running a query. The stored number is kept honest by invalidation, not by luck: every write path that adds or removes a reference rebuilds the count for the affected nodes, and the delete paths do too — a permanent delete (`object.delete {permanent: true}`, `trash.empty`) rebuilds the counts of everything that lost an edge, plus the deleted subtree's ancestors (their descendant counts). The expanded list, by contrast, is a live query over the edge index — so if a badge ever disagrees with its own list persistently (a count with "No linked references"), the stored count is stale, and the repair is to rebuild `node_stats`: it is a derived projection, so a rebuild converges it to the edge index exactly.
- **Unlinked mentions shows no eager count.** Computing it *is* the expensive query — it is a full-text search for the page's literal name across the workspace, excluding blocks that already link to the page. Pages only; blocks do not get this section. **Date pages do not get it either** (owner 2026-10-09): the deterministic day/month/year family carries no Unlinked mentions section — the literal date text those pages accumulate is noise, never a discovery surface — and the count read is skipped there entirely.
- **Results cache** per section until an invalidating notification lands (a content, class, or property edge change).
- **Blocks get backlinks in place.** A block with backlinks shows a count badge in the right gutter; toggling it expands the linked-references query scoped to that block, inline beneath it — the query runs on first toggle, per the contract. The block-level backlink gutter renders on every block row with backlinks — except the read-only list projections where the count is reference noise: the Child pages tree and the Class View's "Extended by" list, which pass the hide flag (owner 2026-10-13).

Backlinks list *actual* links — but the backlinks view can be narrowed by facets over inherited links: Jane's backlinks filtered to `refset ∋ ACME` shows only the Jane-mentions made in the context of ACME, even when the ACME link lives on a parent block (Logseq's linked-references filtering, generalized — see [philosophy.md](../philosophy.md#what-we-took--and-the-wounds-that-became-our-rules)).

**The web client renders the page-level sections** — backlinks and unlinked mentions (pages only: an FTS over the page's name excluding already-linked sources, with per-row Promote/Ignore), plus child pages — as TWO normal NodeCollection sections beside Child pages (owner 2026-10-09, the tab strip's retirement): each rides the shared collapsible-section chrome (the header IS the section header — the tab row is gone) with the hosted view chrome (the tab bar, the add-view +, the view switcher, the quick search — the generic collection chrome is [views.md](views.md#hosted-tab-bar-chrome)); the two hosted reference sections name their count on the active tab's badge (naming the open tab's displayed rows), while Child pages — no tabs — names it in the section-header count badge (owner refinement 2026-10-23: exactly one count per section, on the tab when tabs exist, on the header when they don't). The hide-when-empty ruling is per-section and covers every system section: Backlinks renders only while it has backlinks, Unlinked mentions only while it has unlinked mentions, **Child pages only while the page has children** (owner 2026-10-12 — the main-surface always-render exception retired; a live filter emptying a section keeps it — the gate reads the unfiltered counts). Backlinks starts EXPANDED (its read is cheap, and it is the incoming direction); Unlinked mentions starts COLLAPSED — its list query is the expensive FTS pass, and the collapsed start keeps it lazy behind the first expand (a collapsed section executes no query, and its rows cache across a silent collapse/expand). An expanded section re-runs its query when a notification lands. Embedded feeds keep the ruling (read-only, childless hides). The Backlinks section is the one home for the incoming direction — the old right-rail References panel rendered the same `getLinkedReferences` data and was deleted (one home, no duplication). Every collection view here sorts through the shared sort-button ruling ([views.md](views.md#the-sort-button)).

**Bound verbs surface in both**: a property value over a bound verb schema (the create-and-bind gesture's object/multi property, the designed targeted path) projects into the edge index with the schema id as its verb, so the target's backlinks — page section and block gutter alike — list the source with a quiet pill naming the schema ("supports", "cites"). The verb-mark-on-a-word itself stays targetless (typed-link target resolution is the deferred design) — the pill names the designed path, never a heuristic guess. The classed-nodes section rides with the Class View ([classes.md](classes.md)).

**Reference sections** — below the page's content, the page's references are two normal sections beside Child pages (owner 2026-10-09, the tab strip's retirement): **Backlinks** lists what points AT the page (grouped by the referencing page) and starts **expanded** — its query runs on mount and re-runs on changes; **Unlinked mentions** (the "someone typed the page's name without linking it" section) is the only one with row actions (below) and starts **collapsed** — its list query is the expensive full-text pass, so nothing loads until you first expand it, and its rows cache across a silent collapse/expand. Their rows are the shared collection rows themselves (owner ruling 2026-10-21 — "like any other section": one inert row per referencing block, children folded behind the chevron, the bullet opening the source; the retired Logseq-era inline editable subtree stays gone — and the breadcrumb trail that retired with it is back since 2026-10-22 as shared outline chrome above every collection row, minus the containing-page crumb the group header already names; the bound-verb pill and the unlinked Promote/Ignore pair ride the row's trailing seam). One refinement (owner 2026-10-20): a referencing **page** — one whose own body mentions the target or whose own property values point at it — never sits inside a group named after itself; it renders as its own top-level row, in a separated flat outline before the page groups. The quick text search rides the global search's priority ranking (exact titles first), not a plain substring. Each section hides entirely while its own count reads 0 (a filter emptying one keeps it — the gate reads the unfiltered counts), and each carries the filter chrome at its body top — the structured-filters panel is [queries.md](queries.md#section-filters)'s. **Date pages are the exception**: the deterministic day/month/year pages carry no Unlinked mentions section at all — the literal date text they accumulate is noise, never a discovery surface — and the count's full-text pass is skipped there, so a date page shows Backlinks only.

**Unlinked mentions answer back.** Each row offers two actions: **Promote** turns the literal mention into a real link (the literal name match in the source block rewrites into a mention, and the row honestly moves to Backlinks), **Ignore** hides it on this device — a per-device dismissal that never touches the log.

Blocks stay quiet by default: backlinks aggregate mentions per containing page — a page that references the target from its own body (a mention or a property value on the page itself) is no group at all: it renders as its own top-level row, in a separated flat outline before the page groups (owner 2026-10-20). Search ranks page-title literal matches ahead of block hits (with block hits labeled by their containing page), and queries default to root scope. When a bullet matters enough to stand alone, you promote it ([pages.md](pages.md#promotion-and-demotion)).
