# Properties

Typed, class-bound attributes: the Properties panel on the page, the value cells and their contracts, inline property buttons on blocks, and the schema layer. The schema layer from the CLI (`notees property`, `object property set|delete`) is [cli.md](../cli.md)'s; property conditions in filters are [queries.md](queries.md)'s; the query language's property predicates are [api.md](../api.md)'s.

## The properties panel — layout and contracts

In the main page layout the content card splits into three columns, the two side columns riding as cards nested inside it — the same card element the main content container wears: the first (1/3) hosts the **Properties panel** (the properties sidebar) — a set of rows, one per property, each a property-name row (hints included; click for the settings, right-click for the row actions) followed by its value-cell row, spanning the card's full width; the panel collapses via the properties toggle in the nodeview top bar. Its first section is the **Aliases** row (one pill per alias, × to clear, "+ Add alias" to link a new one — see [links.md](links.md#aliases)). The second column (2/3) is the nodeview proper with auto height under the bar (it scrolls when the content outgrows the cell) — and the footer is gone from this column: it rides the context column's bottom section now (word count and the Created/Updated stamps, pinned to the card bottom; owner 2026-10-09 — [pages.md](pages.md#page-chrome--what-sticks-and-where)). The nodeview top bar itself spans the whole card above the column split (properties toggle + classes pills left, the blocks view switcher + context toggle + "…" menu right, over a full-width divider), so nothing rescales when a panel column shows or hides.

Compact renders (sidebar peek cards) keep the in-flow "Properties" section instead: the same rows as a label-left list under the header, collapsed by default (class-bound defaults dimmed until edited; "Add property" picks any schema or creates one) — embedded feed entries (the journal feed, the calendar's day pages) omit the section entirely, divider included, while the page carries no property rows, so a feed never stacks empty "Properties 0" headers. Focus mode is not a secondary surface — it keeps the panelled layout and hides the chrome; the full ruling is [pages.md](pages.md#focus-mode)'s.

The panel lists a node's effective property values: authored values win, class-bound defaults render dimmed until edited, and every write is an ordinary op. **Adding a property assigns it without a value** (owner ruling 2026-10-23 — assign now, set the value later): "+ Add property" declares the property on the node and the row renders immediately as an empty cell — the same placeholder the bound-but-empty rows render ("Type something" for text, "Select" for node/date, an empty field for url/email/number) — and the first edit authors the value; leaving it empty leaves the declaration in place (an assigned row never fabricates an empty value). Class-bound properties are **virtual until realized** (the virtual/realized assessment, owner 2026-10-23): the picker leads with them as **"Realize … · from <class>"** entries — the same assign, labeled by the nearest binding class (own bindings before extends-ancestors) — and schemas already realized on the node (valued or pinned) drop out of the list entirely, since their rows already render. Realizing pins the property to the node: it survives class removal and binding edits on its own, while a never-realized bound property disappears the moment its class stops supplying it. Until realized, the virtual property still SHOWS as an empty row with the from-class hint — scalar types (url/email/number) included; typing into the cell is the de-facto realize. **Remove from node** drops the declaration together with any authored values. **Empty property** (the row's context menu) clears every value of the property but KEEPS the assignment — the row returns to its empty cell (a class-bound default resurfaces). Assignment is panel chrome, not a rule: it gates nothing — a property's scope still says which nodes may carry it, and values written any other way (CLI, API, import) need no declaration. The surface is hardened:

- **Single values select, multi values pill.** A single-value node-typed or date property renders as a full-width selection dropdown: the content area shows the selected node as **one compact pill** — the same element the classes list renders, tinted with the linked node's effective color (a date shows its display name) — never the node's subtree; empty shows a muted "Select" placeholder, clicking opens the node/date picker anchored at the cell, and a clear affordance unsets the slot. Multi-value node-typed properties render each value the same way — **pills, never subtrees** — with the hover-reveal × and the label click opening the node.
- **The datetime picker is one canonical popup.** A datetime value (point or range) opens the same popup everywhere it is edited (panel row, multi pill, table cell): a natural-language date field ("today", "Feb 14", "next week" — plus a wall-clock time, "tomorrow 14:30"), a month day-grid under a `month ⌄ / year ⌄` dropdown header with ‹ › navigation (the days↔months↔years zoom grids stay; the schema precision is the commit ceiling), a **Suggestions** column (Yesterday / Today / Tomorrow / In 1 week / In 2 weeks, the current date checked), an **All-day** switch (on by default; off reveals a 24h HH:MM time input per end), a **Range** switch (off collapses to the point, start kept and end dropped silently), a **Repeat** row (day precision — [calendar.md](calendar.md)), and **Remove**. Full-day is the absence of a time and is the default for every new value.
- **Empty cells say so.** An empty text property renders the full-width "Type something" placeholder input (typing authors the first carrier block); empty single-value node/date cells show the "Select" placeholder.
- **Broken stays visible.** A property value that points at a deleted node is not silently dropped: the value renders the raw id honestly — the dashed, muted pill chip on multi-value rows, the selection cell's broken state on single-value rows — and restoring the target heals it. Keep-value + render-broken is the graph-wide rule (SCHEMA.md "Broken references").
- **Values have history.** Right-click a property → **Value history…** renders the property's writes from the server operation log (newest first). Offline, the modal says so instead of guessing.
- **Types convert honestly.** The settings modal's **Convert…** changes a schema's type the one honest way: create the new schema, copy the values that map, list the ones that don't (dropped only with explicit confirmation), re-point the class bindings, delete the old schema.
- **Options carry color.** A select option can wear a data-palette color; its pill tints, and the settings modal edits it per option with one color dot.
- **Aliases are names.** The seeded `alias` property gives a page alternative names — searchable like the title, resolvable by exact match, and matched by unlinked references ([links.md](links.md#aliases)).
- **Text values are blocks.** A text property renders its values as editable blocks in the row — never repeated label entries. Enter on a multi-value property starts the next value (a sibling block registered as the next entry); Enter on a single-value property nests a child block under the value, whose children are its lines. The block is the value: it indexes, links, and deletes like any block.
- **Cleared text returns to empty.** A text value whose carrier has no content and no child blocks does not linger: the panel unsets it automatically and the slot returns to its empty state (the unset trashes the orphaned carrier — recoverable from trash). The pass runs when the panel sees the emptied carrier and when focus leaves the row; while the caret is inside the row a just-minted empty value (Add pill, Enter) is left alone so it can be typed into. A dead reference whose target node is gone counts as contentless and is unset the same way; one that exists but no longer renders inline (e.g. promoted to a page) keeps its recovery cell.

Click a property's label for its settings (rename, date precision, select options — each option carries an optional color that tints its pill and an optional icon), right-click it for the row actions: **Value history…** renders the property's writes from the server operation log (newest first), and **Convert…** changes the type via the blessed delete+recreate flow. A property value that points at a deleted node is not silently dropped — it renders the raw id in a dashed "broken" pill, and restoring the target heals it. **Text properties are blocks**: a text value renders as an editable block (with its own children) right in the row — not a repeated label per value. On a **multi-value** text property, pressing **Enter** at the end of a value starts the next value (a sibling block registered as the next entry); on a **single-value** one, **Enter** nests a child block under the value — the value is one block whose children are its lines. **Drag a block from the page's body onto a text-property row** to make that block the value's carrier: an empty single-value slot takes the drop, an occupied one never overwrites (the drop is refused), and a multi-value slot appends the block as one more carrier — the block stays in the tree and its render zone switches body→panel by the carrier rule (same-owner body blocks only: a foreign drag shows the no-drop cursor).

## Inline property buttons

A selection (or boolean) property can pin its value onto the block itself, not just the Properties section: open the property's settings (click its label in any Properties section) and pick its **value display** — **Next to bullet** renders the value as an icon button right at the block's bullet, **Before content** sets it just ahead of the text (the default **Properties panel** keeps it in the section only). The button wears the current option's icon and color, so state reads at a glance — the built-in task **Status** options are circles: gray Backlog, yellow Pending, orange Doing, blue Reviewing, green Done, red Cancelled — and clicking it opens a small picker to change the option without leaving the block. The task Status button rides a task row in every list view too ([views.md](views.md#the-list-view-is-the-outline-view)). A property shown this way leaves the collapsed Properties section (the button already surfaces it). The same settings panel hosts each option's icon and color, plus the **Read-only** and **Hide when empty** property flags (**Required** stays per-class: the class page's property list sets it per binding).

## The typed-properties write path

From the CLI and API, class members carry structured values beside their content — `object property set` writes one (the schema argument is a uuid or a name; the value parses as JSON when it can — `42`, `true`, `{"nodeId": "…"}` — and stays a string otherwise), `object property delete` unsets a slot. The write path is shape-checked per schema type: a datetime or object-typed property takes a node reference (a date is a node — see [calendar.md](calendar.md)), a text property takes a plain string or a block reference, and a mismatched shape is rejected with an error rather than stored. One **Datetime** property type covers every date need: a value is a point `{"nodeId": "…"}` or a range `{"start": …, "end": …}` on the year/month/day node chain, **Full-day** by default — set a wall-clock time by switching the picker's **All-day** off (24h `HH:MM`, day precision only), span a period with the per-value **Range** toggle, jump via the picker's **Suggestions** column (Yesterday / Today / Tomorrow / In 1 week / In 2 weeks), or clear with **Remove**. Deleting a text property whose value references a carrier block moves that block to the trash (recoverable with `object restore`); plain-string values simply clear. The CLI transcript and the property-schema commands (`notees property …`) are in [cli.md](../cli.md#a-real-session).
