# Whiteboards

A whiteboard is a page (or an embedded block) whose content token carries the spatial canvas — a spatial view of the node's subtree, not a separate kind of content. A whiteboard is **a node classed `whiteboard`** (the what-it-is axis, [philosophy.md](../philosophy.md#what-it-is-lives-in-class-data-lives-in-tokens)); the `whiteboard` content token carries its geometry: shapes, strokes, connectors, and per-card `x, y, w, h` keyed by node id. The `whiteboard` class is seeded in the catalog, the token is part of the normative grammar, and the web app renders the spatial canvas. The model, precisely:

- **Cards are blocks.** Double-click empty space (or use the Card tool) to create a card: it is an ordinary child block with a position and size — full content grammar, backlinks, search indexing, focused view, classing — so it indexes into search, takes classes and properties, and zooms like any block. The tree holds content; the token holds geometry, keyed by node id. Dragging a card is a layout update — debounced and coalesced into one write per gesture (no per-mousemove op spam, no new sync primitive). **×** on a card deletes the block — cards are graph nodes and are never erased by the eraser.
- **Shapes are geometry only.** Rectangles, circles, connectors, freehand strokes — layout-token data with no identity and no node overhead.
- **Semantic text lives in cards, not shape labels.** Text that matters gets a card: shape labels and the Text tool are chrome — they live in the layout token, never in the graph. A lint may suggest promoting a label to a card — the design law's usual enforcement ([philosophy.md](../philosophy.md)).
- **One node, three views.** The same children render spatially (the whiteboard), as an outline (the outliner), or focused (Focused Block View) — because they are the same nodes. Its cards index into search and the graph naturally — no separate "whiteboard content" that search can't see.

A whiteboard can live fullscreen (a parentless node) or embedded as an inline child of any block (`/whiteboard`). On the main surface a fullscreen whiteboard page fills the whole content card — the page chrome (title, panels, footer) steps aside and the canvas is the card's sole content, edge to edge (the overlay host is sized for this second consumer — [pages.md](pages.md#presentation-mode--the-note-is-the-deck)); embedded feed entries and in-block boards keep the bounded in-flow canvas. Embedded whiteboards keep the full toolset; pan and wheel-zoom stay with the surrounding page (embedded canvases keep the full toolset minus pan/zoom — scroll priority).

## The canvas

- **The tool palette** — Select/move, Card, Sticky note, Rectangle, Ellipse, Line, Arrow, Pen, Highlighter, Eraser, Text, Connector. Draw tools drag to draw (a bare click places a default size); place tools put one item and return to Select (one-shot draw tools that return to select after each gesture). The **connector** snaps its endpoints to the edges and centers of nearby cards and shapes. Sticky notes are cards with a node color (recolor them, or any selected shape/stroke, from the color swatch that appears with a selection). The **pen** draws freehand strokes; the **highlighter** lays a translucent wide marker stroke (commits the layout schema's `highlight` marker — a translucent wide stroke in the marker color); the **eraser** drag-removes strokes and shapes under it (it stays armed until Esc — cards are graph nodes and are never erased; their **×** deletes the block). Colors and stroke-width tiers ride the selection.
- **Multi-select** — drag on empty space box-selects; Shift+click adds or removes; dragging any selected card moves the whole selection. With several items selected the toolbar grows alignment/distribution buttons and a stroke-width control. Dragging any selected card moves the whole selection; every gesture coalesces to one content op.
- **Keyboard** — Delete/Backspace removes the selection, arrow keys nudge it (Shift = one grid step), Esc exits the active tool.
- **Context menu** — right-click any canvas object (card, shape, stroke): **Delete**, **Bring to front / Send to back** (shapes and strokes — the geometry's z-order), and **Color** (cards color the node; shapes/strokes color the geometry).
- **Navigation** — mouse wheel zooms (fullscreen), middle-drag pans, the corner minimap clicks/drags to a spot, and the zoom cluster offers −, +, Fit, and 1:1. **Snap** quantizes drawing, placement, and drags to the dot grid (a snap-to-grid toggle riding a world-anchored dot grid), and the minimap takes click-to-navigate.

Not shipped: the remaining breadth (15-shape set, sticky-ended connectors).
