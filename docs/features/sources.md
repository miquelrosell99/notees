# Sources

The source library: one `source` class family covering the Zotero item-type roster, a resolver that turns an identifier (or a PDF) into a prefilled source, citekeys generated from your pattern, bibliography export (.bib / CSL-JSON) over any selection, and CLI imports (BibTeX / CSL-JSON / Zotero RDF) that reconcile an external bibliography into the library. A source is an ordinary node — in the graph, queryable, backlinkable; its files are `attachments` ([properties.md](properties.md)'s dedicated asset row) and its notes are ordinary child blocks ([pages.md](pages.md)). The family toggle and the class machinery underneath are [classes.md](classes.md)'s; the export dialog's other formats are [exporting.md](exporting.md)'s.

## The source family: 39 type-classes

`source` is the family base; 9 everyday types are enabled from the start (`book`, `journal_article`, `thesis`, `document`, `film`, `song`, `tv_series`, `conference`, `web_page`) and 30 more carry the Zotero long tail (`book_section`, `conference_paper`, `patent`, `dataset`, `artwork`, …). 18 of the long-tail types seed **archived** — off your pickers and the create list, not out of the graph: archiving is visibility, never absence. An archived type still extends `source`, still answers `class:` queries, still exports. Two doors turn one switch: pick the type's card in the classes gallery, or check its row in the Sources settings list below. Each type carries its Zotero field set (a journal article shows container/volume/issue/pages/ISSN; a patent shows patent number and jurisdiction), all inherited from the family base. You can also define your own source subclass at runtime — `extends [source]` joins the family.

## Adding a source

Four doors lead to the same dialog: the command palette's **Add source…** (hidden offline, the share-target pattern), the **Add source…** button in the Sources settings section, a node picker's **Create source from link** row, offered whenever what you typed into a create row looks like a DOI, ISBN, arXiv id, or URL — and the global **New** flow is the manual door: picking a class there opens the class-driven create form (every class — source types, persons, your own classes — with the class's bound properties loaded dynamically, staged, and flushed to the log only on Create). The resolver's magic wand is this dialog, never the class pick. The dialog takes one input — a DOI, ISBN, arXiv id, a URL, or a PDF link — plus a PDF drop zone (pick or drop one file, the asset-upload register). An identifier resolves against the metadata providers; a URL is fetched server-side and scanned for the DOI printed in its PDF; a file you pick uploads to the asset store and links to the created source (a failed upload creates no half-source). On success the create form opens **prefilled**: type, title, the type's venue fields, year, DOI, ISBN, URL, publisher, and authors/editors.

The honest edges: a PDF with no DOI says so and creates nothing; the resolver-off state points at the Sources settings and offers **Add manually** (the same create form, seeded from what you typed — a plain URL lands as a weblink, its URL the title); a provider failure surfaces the provider's message; a resolved type that is archived is re-enabled automatically, the un-archive riding the same undo step as the create. A DOI, ISBN, or citekey already in the library shows an **Already in your library** warning with a link — creating again stays allowed. An empty citekey fills from your pattern when auto-citekey is on, a deterministic `a`/`b`/`c` suffix disambiguating collisions (compared case-insensitively, continuing past `z`).

On the source's metadata panel, the **Citekey** row carries two affordances. The regenerate button inside the field (circular arrows, at the right edge) re-renders your pattern from the source's current metadata — first author's family, the publication year, the title — and collision-suffixes against the rest of the library, skipping the source's own current citekey so regenerating over unchanged metadata is a no-op. The write rides the ordinary property write, so it undoes like one. The pin button beside the property name (a pushpin) freezes the citekey against automatic changes: generation is **always on while the Sources feature is on** — a missing citekey fills when the source is created or opened, and an unpinned value re-renders whenever the authors, publication date, or title change (a deterministic `a`/`b`/`c` suffix disambiguating collisions) — while a pinned citekey never changes unless you edit it. Typing a citekey by hand pins it automatically (a hand-chosen key is a deliberate choice, never auto-overwritten); the button unfreezes it, and a second click pins the current value again. The button disables while the citekey is empty — nothing to protect. An empty citekey reads like every other empty text property — the muted "Type something" field.

## Authors: plain text, and the people graph

Authorship is deliberately dual-track, and the two tracks never write each other. **`authors`** is plain text — one name per value, in BibTeX "Family, Given" form (the create form splits a pasted `;`- or newline-separated list, a comma lives safely inside one name). It is the citation and export source of truth, and creating a source never spawns person nodes. **`linkedAuthors`** is the people-graph view: node-typed links to `person`/`organization` agents, drawn as chips with backlinks, carrying zero availability semantics — you link the authors you care about, whenever you care, by hand. Authorship reads use `authors` first and derive names from the `linkedAuthors` targets only when the text track is empty (read-time only, never written back).

## The bibliographic property set

The family binds one shared base set on `source` — `Authors` and `Editors` (free text, one name per value, "Family, Given"), `Citekey`, `DOI`, `ISBN`, `Publisher`, `URL`, `Publication date`, and `Attachments` — and every type-class binds its own Zotero field list from the 85-schema pool (Volume / Issue / Pages / ISSN / Abstract / Edition / Accessed / Book title / Publication title / …, one schema per Zotero field, each scoped to the source family and bound per class). Nearly every field is a **plain text scalar on purpose**: a field holds what the source says, with no validation fights — flexibility over formality. Four exceptions are typed, because their values are graph citizens:

- **`Linked authors`** — object-typed links to `person`/`organization` agent nodes (the target filter is implicit in the type), the manual curated relational form above. Nothing machine-writes it: not the resolver, not the add-source dialog, not the bibliography imports.
- **`Publication date` and `Accessed`** — datetime values on the date chain: the value references the chain's year (or day) node, a date is a node, so both properties sort, query, and group like every other date.
- **`Attachments`** — asset-typed values pointing at asset nodes (the type is the filter), rendered as the dedicated file row with **Upload** and **Link** ([assets.md](assets.md) covers the asset side).
- **Cover / Banner images** — not properties at all: wire node fields (`coverAssetId` / `bannerAssetId`) referencing asset nodes, exactly like any page's cover ([pages.md](pages.md#page-chrome--what-sticks-and-where)); the CLI's `notees cover set` composes the whole invariant in one gesture.

Property panels render the set alphabetically by name, extends-aware (a journal article shows its own volume/issue/pages beside the family base's, never a sibling type's field) — the class machinery is [classes.md](classes.md)'s and [properties.md](properties.md)'s.

## The Sources hub

The sidebar's **Sources** entry opens `/sources`, the library manager surface (a Zotero-parity view over the source family). The surface owns its URL and its tab title: the address bar carries the filtered state — `?type=<classKey>&q=<search>&sort=<field>:<dir>` — so a reload or a shared link boots back into the same filtered library, and the tab reads "Sources". Three panes compose the shared panelled frame: the source-type facets on the left, the items table in the middle, the type-aware detail editor on the right.

The **facets pane** lists every source type with its live count — the enabled types alphabetically, the archived types (the same archive flag the gallery and the settings toggle — two doors, one switch) collapsed under **Hidden types**, each with an **Enable** row that un-archives the type in place. Picking a type filters the table and lands in the URL; the query data layer lives in `apps/web/src/features/sources/sourcesQuery.ts` — one grouped read over the live source family feeds every facet count, the display projection reads authors per the dual-track read contract (`authors` text first, `linkedAuthors` agent derivation when empty), the venue from the class's container binding (journal → publication title, book section → book title, web page → website title), and the year from the publication-date chain; the search box filters title, authors, and citekey together.

The **items table** renders the library through the shared collection table: one row per source, the columns reading the display projection (type, title, authors, year, venue, citekey, attachments). Click a column header to sort — the URL carries `?sort=field:asc|desc`, so sorted views are linkable, and sources with an empty value sink to the bottom in both directions. The toolbar lives in the surface top bar, not over the table — and it is the search box beside the Duplicates mode switch; the filtered row count reads as a badge next to the **Sources** title, and the panel toggles lead the bar, left of the title — the general hub convention. The detail pane renders only while a source is selected (the toggle AND a selection; with nothing selected there is no pane at all). Pane visibility is device-local session state, remembered on this device only. Arrow keys move the selection and Enter shows the selection in the detail pane; clicking a row selects it too. An empty library is stated honestly in the table pane, with the New flow as the door — press **New** in the top bar, pick a source type, and resolve a DOI, ISBN, arXiv link or URL (or fill the form by hand). Titles read as text everywhere: a source saved with a markdown link (`[label](url)`) or image (`![alt](url)`) as its title shows the label/alt text, never the raw bracket syntax.

**Duplicates** (the mode switch beside the search box) groups the library's probable duplicates into clusters — one group per cluster, headed by what matched (a shared DOI, ISBN, or citekey — the header names it — or a similar title with the same year or first author), the member rows reading the same projection cells as the table (title, authors, year, citekey, DOI). The type facet and the search box narrow this mode too. One **Merge** button per group opens the merge dialog: a dropdown of the group's members picks the kept source (the first member by default), a dry-run line previews the merge — how many children, classes, and properties move or fill empty slots — and the danger confirmation states the outcome: everything consolidates into the kept source and the merged copies go to the **trash** (restorable like any trash, and each merged copy undoes as one step). After the merge the group is gone from the list.

The **detail pane** (the right cell) is the selected source's type-aware editor. Its type chip names the same primary type the table row carries; the title edits in place (click, type, Enter — the title IS the content, one write through the content path); and the field set below is the workspace's shared metadata properties panel over the effective read — extends-aware, so a journal article shows its own volume/issue/pages fields (empty ones included, ready to fill) inherited beside the family base's, and never a field its type doesn't bind. **Open** takes the source to the page view; **Delete** asks in the shared confirmation dialog (naming the source, never an id) and trashes it, clearing the selection.

## Settings → Features → Sources

The Sources section under the workspace feature toggles:

- **Citekey pattern** — the token language `[auth]`/`[auth:lower]` (first author's family), `[year]`, `[title]`/`[title:lower]`/`[title:lower:N]` (first N words), plus literals; default `[auth:lower][year][title:lower:3]`. The input previews a sample entry live (Lovelace, Ada / 1843 / "Notes on the Analytical Engine" → `lovelace1843notesonthe`), an invalid pattern shows its error and is never written. The committed pattern governs every generation; a PINNED citekey is never recomputed, while an unpinned one follows the pattern as it tracks metadata changes. Generation has no toggle — it runs whenever Sources is on.
- **Metadata resolver** — look up DOIs/ISBNs/arXiv ids when a source lacks metadata. See the privacy note below.
- **Source types** — all 39 type-classes as checked rows: unchecked is archived, the same archive flag the gallery respects.

Every settings change is one write to the feature row, so the keys never clobber each other — and a family toggle off/on keeps them (the row is one whole-row unit; turning Sources off hides the family's surfaces, instances keep their data).

## Export: .bib and CSL-JSON

The export dialog registers **BibTeX (.bib)** and **CSL JSON** beside the other formats. Both are one document over the whole selection — every source-classed node becomes one entry, batch included, deduplicated by node id; body blocks are content, never entries. Entries project through the same dual-track read everywhere ([exporting.md](exporting.md)): `authors` first, `linkedAuthors`-derived names when empty, the type's venue fields through its Zotero bindings. The LaTeX export's bibliography reads the same contract.

## Importing a bibliography (the CLI)

The CLI reconciles an external bibliography into the library — the export's counterpart. Three formats share one pipeline, `notees import bibtex|csl-json|zotero-rdf <file>`: a `.bib` file, a CSL-JSON array, or a Zotero RDF export all parse to the same item shape and ride the same semantics ([cli.md](../cli.md); the in-app Import Workspace modal — Notees dumps, Markdown, Logseq — is [import.md](import.md)'s, a different surface).

- **Matching — citekey upsert.** The Citekey property match is authoritative: an entry whose citekey already lives on a source *updates* that source, never duplicates it. A node titled exactly `citekey` or `@citekey` with no Citekey property is **adopted**, not duplicated — renamed to the spec title (title-is-content), the Citekey set, and the spec's source class assigned when the node's class closure isn't eligible to carry it; several same-titled nodes adopt the first and count the rest as ambiguous.
- **Fills — Notees wins.** A matched (or freshly created) source is filled only with the properties it does not already hold; values you set by hand are never clobbered. The zotero-rdf importer fills the full field set beyond the shared CSL fields (abstract, volume/issue/pages, ISSN, language, short title, extra, identifiers, the container title — Book title for a book section, Publication title otherwise); Zotero tags and file attachments in the export are skipped and counted, never guessed into classes or assets.
- **Idempotency.** A second run of the same file plans and writes nothing — the imports are re-runnable by construction. `--dry-run` prints the whole plan (schemas ensured, per-entry action and fills) and writes nothing; `--no-create` is match-only mode (update and adopt, never create).
- **The import ruling.** Bibliographic imports **never create person/organization nodes and never write Linked authors**. Creators are bibliographic metadata: they land on the text `Authors`/`Editors` properties only — "Last, First", order preserved — and `Linked authors` stays manual-only, the relational people-graph track you curate by hand. The export's dual-track read is the mirror: it reads the text track first and derives from Linked authors only when the text is empty, so a hand-curated link still shapes exports.

`notees import logseq-db <file.sqlite>` is the CLI counterpart of the in-app Logseq DB reconcile: it decodes the transit-encoded sqlite client-side, runs **dry-run by default** (`--write`/`--yes` applies), and reconciles by uuid — missing nodes are created with their preserved Logseq uuids, matched nodes are never renamed, property values fill only empty slots (Notees wins; a `newer-wins` title strategy is available), and property names map through an explicit validated table. It is a whole-graph drift reconcile, not an author-strings importer: node references move only where the Logseq graph itself carries them. A re-run reconciles instead of duplicating.

## The resolver's privacy note

Resolution asks three public metadata providers — **Crossref, Open Library, and arXiv; that list is complete.** Only the queried identifier leaves the server: no request body, no workspace content, nothing else. The resolver is the server's only outbound egress. Your workspace's resolver toggle gates it (absent = on), results cache for 24 h on the server, and a provider that fails or times out (10 s) answers with an honest error instead of a stall.

## Deliberately not here

The designed-not-built register, stated plainly: **in-editor `cites` citations** (a `cites` verb marking text with a source + locator — the model is settled, the surface is not built), a **PDF reader** (PDFs attach as files; nothing renders them in-app), and **Zotero sync** (import maps Zotero item types; there is no live sync). The source library ships what is on this page — no more, and it says so.
