# AGENTS.md

Notees — a self-hosted, privacy-first, local-first **personal information environment**: one object graph (nodes carry `is_class` + `is_embedded`; "page" and "block" are structural roles, not node kinds; typed properties, typed link marks, assets) whose only authority is an immutable **operation log** (envelope **v3**); every SQLite database (server, browser worker, CLI) is a derived projection of that log. TypeScript everywhere (Node 22, pnpm 9).

## Commands

- Install: `pnpm install` · Build: `pnpm -r --workspace-concurrency=1 build` · Test: `pnpm test` (all green = blocking gate). Full command table, the fixture gate, and the add-an-op recipe: `docs/developers/development.md`.
- **Dev-condition exports**: vitest reads `src`, `tsc` reads `dist` — after changing a package's public API, rebuild its dist before typechecking dependents.
- Deploy: plain Docker, `docker compose build` + `docker compose up -d` from the repo root. The live `compose.yaml` + `.env` are **gitignored host-local artifacts — never committed** (owner ruling 2026-10-22, enforced by the `rosellramos-coding-standards` skill); the repo ships `compose.example.yaml` (+ a dev variant) and `.env.example` only — fresh hosts `cp` the examples. The compose project name derives from the folder name (no `name:` pin) — keep the repo folder `notees` on production hosts. The live data dir binds `${NOTEES_DATA_DIR:-./config/notees/sync}` — the fleet host sets `NOTEES_DATA_DIR` in `.env` to `/etc/periphery/stacks/notees/config/notees/sync` (fleet stacks location, borgmatic backup source; `relay.db` never lives in the dev repo). Then the `verify-min.mjs` smoke — **invoke the `notees-operations` skill first** (plus `deployment-runbook` for the deploy/rollback discipline). Full runbook + the ghcr/CI publish path: `docs/developers/deployment.md`; the companion clients (GTK/Flutter/CLI — each owns its releases) are documented in `docs/developers/README.md`.

## Invariants (design law — read the linked homes before changing the model, wire, or appliers)

- The operation log is the only authority; semantic state only — device state is never an op (`docs/developers/architecture.md`).
- Conflict semantics: **LWW by HLC** (scalars, property values) · **OR-Set add-wins** (class/collection membership) · tag membership mirrors the OR-Set with a strictly-greater add tiebreak (deliberate asymmetry — cheat sheet in `docs/developers/development.md`).
- **Title-is-content** (owner 2026-10-01): no `name` field on the wire — a node's title IS its text content; a page's own content MAY carry inline rich tokens (mentions, external links — the header title is a full block row), class content stays text-only, and display-name derivation still flattens to text (`SCHEMA.md`).
- **Embedding model** (Revision 12, owner 2026-10-16; Revision 11's `present_as_main` retired and inverted; the parent-page condition joins 2026-10-15): nodes have no page/block kind — only `is_class` + `is_embedded`, separating classification (`is_class` — what the node represents) from parent relationship (`parent_id`) from embedding (`is_embedded` — whether its content belongs to the parent's body). A node in the **Page role** renders with document chrome: `is_class = 1`, OR no parent (`parent_id IS NULL`, standalone by definition), OR `is_embedded = 0` on a parented non-class node **whose parent also renders with document chrome** — a class or embedded-block parent makes the standalone claim inert. A node in the **Block role** is any other parented non-class node — `is_embedded = 1` (the DEFAULT for parented nodes), or the claim inert under a non-page parent — inline in the parent's body, no title/chrome. An **entity** (a classified thing — meeting, quote, city) is independent of the role: it may be embedded or standalone (`rendersWithDocumentChrome` / `rendersAsInlineBlock` in `packages/domain/src/node.ts` are the two branches). The condition is write-time enforced (fail-loud `MoveGuardError`: no create/promotion/move of a standalone node under a non-page parent, no demotion of a parented page with standalone children); old logs are normalized by `scripts/migrate-main-parent-page.mts` and the Revision-12 rewrite `scripts/migrate-is-embedded.mts` (LOCKSTEP-PENDING: GTK/Flutter converge on the `is-embedded-parent-page.json` fixture and the rename). Wire is envelope **v3**; retired keys are rejected outright — **no backward compatibility** (owner directive, sole user): migration is a one-time in-place rewrite of the stored log, after which every store re-syncs (`SCHEMA.md` "Node structure"; `migrations.md`).
- **Node fields vs properties**: platform-fixed, cardinality-1 node fundamentals that core chrome or navigation reads or writes (`coverAssetId`, `bannerAssetId`, `aliasedNodeId` — the icon/color precedent) are **wire node fields**, with derived columns as their direct projections. The property system is for user-extensible typed attributes (class-bound, multi-value, defaulted, qualified, query-filtered) — never for platform fundamentals, and property drift is never answered with reserved-schema machinery.
- **Property scope is the sole locality authority** (owner ruling 2026-10-20): a schema's `scopeClassIds` (absent/null = global; non-empty list = local to those classes + their extends-ancestors) says who MAY carry a property; `class_property` bindings carry zero availability semantics (per-class config only — `active`, the soft-unbind flag; `defaultValue`/`required`/`sequence` retired or moved, owner rulings 2026-10-20/21). Class properties render as a PURE ALPHABETICAL list everywhere (by property name, read-time derivation — no order is stored or configurable). Eligibility is extends-aware, enforced fail-loud at write time (`property.set`, `class.property.set`, `property.assign`), and the effective read tags ineligible authored rows `eligible: false` while never deriving defaults for them; the retired `scope` enum is rejected outright (`scripts/migrate-property-scope.mts` rewrites stored logs). Node-level **assignment** (`property.assign`/`property.unassign`/`property.empty`, owner ruling 2026-10-23 — the v1 `node_property` lineage) is first-class log state: a node carries a property with no value (`node_property` presence row, LWW; the effective read synthesizes an empty row), and it carries zero availability semantics like bindings — assignment never gates writes, `unassign` never touches authored values, and `empty` clears every value while keeping the declaration.
- **Impossible states are write-time impossible**: structural invariants (extends DAG, alias-chain acyclicity, class-parenting) are validated at the operation level — loud failure, never applied — and render assumes them; there is no UI for impossible states.
- **System-class extends is frozen** (owner ruling 2026-10-22): a system class's extends mapping is seeded platform structure (the feature-toggle cascade + binding inheritance derive from it) — `class.setExtends` on a system class applies only when the payload equals the seeded parent set (the seed/ensure re-issue path); every deviation fails loud (`SystemExtendsLockError`). User classes stay freely extensible onto system bases; enforcement is never retroactive (SCHEMA.md "Class properties").
- **Date-chain nodes are parent-locked and class-locked** (owner 2026-10-13): a date node's parent IS its deterministic chain parent (year → root, month → year, day → month) and its class set IS its precision's system class (year/month/day, never declared a class itself) — `object.create`/`object.move`/`class.assign`-carrier breaches fail loud (`MoveGuardError`), and the web breadcrumbs + classes row hide their edit affordances on date nodes (SCHEMA.md "Datetime").
- New op types are additive and require protocol fixtures exercising every client applier (TS reference; GTK/Flutter lockstep) before implementation counts as complete (`docs/developers/development.md`).
- Identity is UUIDv7 everywhere; titles/paths/citekeys are attributes, never identity.
- Sync server (PostgreSQL relay) is coordination, not the object database.

## UI primitives

All chrome MUST compose from `apps/web/src/components/ui/fleet/` — one element per file, co-located CSS, barrel-exported, token-only CSS (`variables.css`). No ad-hoc styled controls in feature code. Values that track type metrics or layout take the adaptive form (`1lh`/`em`/`ch`/`%`, `clamp()`, spacing/radius/motion tokens), not fixed px numbers — hard-coded px only where the dimension is genuinely constant (hairlines, tap-target floors). **Catalog, the popup-dismissal seam, the drift classes, and the adaptive-values law: `docs/developers/ui-primitives.md`.**

## Working rules (owner)

- **Docs are part of the change**: any change to behavior, the model, the wire, or the UX updates the relevant documentation in the same pass — user-facing `docs/`, `packages/protocol/SCHEMA.md`, `AGENTS.md` / `.agents/` when they describe changed reality, and the `docs/developers/` runbooks.
- **The changelog is the record** (owner 2026-10-06): what shipped and why lives in `CHANGELOG.md` at the repo root — one entry per shipped slice, newest first. `AGENTS.md` itself is static guidance: never append history, dates, or work-record entries to it; edit it only when the guidance changes. Before implementing, skim `CHANGELOG.md` for recent related work and check `.plans/` for an in-flight proposal folder. A change without its changelog + doc updates is not done.
- **Fleet-agnostic artifacts** (owner 2026-10-06): never hardcode machine names (Tailscale device names), IPs, or tailnet names in code, templates, docs, or notes — write `<host>`, `<tailnet>`, `<lan-ip>`, `<tailscale-ip>`, or "the fleet host". Concrete values live only in gitignored host-local files (`.env`) and per-host operator config; example values in templates must be clearly generic (e.g. `192.168.1.10`).
- **Worktrees live in `.worktrees/`** (owner 2026-10-07, extended 2026-10-08): git worktree work goes in the repo's own gitignored `.worktrees/<slug>/` — never a random sibling folder (`git worktree add .worktrees/<slug> -b <slug> main`). Concurrent sessions on unrelated tasks each default to their own worktree (own branch, install, gate; distinct dev ports — worktrees don't isolate those) so one session's half-done edits can't break another's tests; a solo session or a trivial docs-only slice may stay in the main checkout. Slices land one at a time in the main checkout (fetch, rebase onto the freshest main, fast-forward merge, push — if main moved or `.git/index.lock` is present, another landing is in flight: wait and redo the rebase), and a landed slice cleans up after itself: `git worktree remove .worktrees/<slug>` + `git branch -d <slug>`.
- **Shared record files** (owner 2026-10-08): `CHANGELOG.md`, `README.md`, `docs/`, and `AGENTS.md` are touched by nearly every slice and conflict at merge time by construction — keep edits minimal and anchored (changelog entries prepend under the current date heading, never reorder existing entries) and resolve conflicts by keeping both blocks, never dropping another slice's entry.
- **No transient-internal-doc pointers in the tree** (owner 2026-10-07): code, tests, docs, and CHANGELOG entries never reference `.plans/` proposal folders, design docs, or any internal transient documentation — the durable text stands alone. Internal cross-references live inside the internal docs themselves; the tree carries zero pointers to them.
- **Parallel sessions** (owner 2026-10-08): other agent or human sessions may be working in this repo — and against the same dev environment — at the same time. Detect before writing and before any shared-state action: `git status --porcelain` + `git log --oneline -5` at session start (unfamiliar changes belong to someone else's in-flight task), `git worktree list` (a stale entry from a crashed session gets pruned once confirmed dead — never a live sibling), a present `.git/index.lock`, `docker compose ps`. Handle: never revert, delete, reformat, or commit files outside your task (per-file staging only — never `git add -A` / `git commit -a`); red tests or lint errors in files you didn't touch are another session's in-flight work — report them, don't fix them; avoid stack-wide commands (`compose down`, image rebuilds, DB resets under `config/notees/`, killing processes) without checking who else is using the environment — prefer scoped commands; snapshot-commit your own verified stable states — uncommitted work is one rebase away from gone. Detail: `docs/developers/development.md` + the `agent-repo-workflow` skill.
- **Commit and push when done** (owner 2026-10-08): a finished slice — gate green, `CHANGELOG.md` entry in — is committed (per-file staging only, Conventional Commits) and pushed to the current branch before the session ends. Pushing is standing authorization in this repo; the `agent-repo-workflow` skill's per-push confirmation rule does not apply here. If the remote moved, integrate (`git pull --rebase`), never force.
- **Redeploy what you ship** (owner 2026-10-08): the running stack carries the local build, not the repo — a code change is not live until the changed services' images are rebuilt and the stack recreated: `docker compose build <services> && docker compose up -d`, then the `verify-min.mjs` smoke (expect `VERIFY-PASS`). Build/up from the LIVE STACK FOLDER on hosts with the source/stack split (owner 2026-10-19 — the Checkout `config/` is not the live data), never from the checkout; invoke the `notees-operations` skill first; prefer scoped builds (only the changed services) over stack-wide rebuilds per the parallel-session rule. Docs-only or repo-only slices (no runtime behavior) need no redeploy.
